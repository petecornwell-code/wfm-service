The TypeScript interface bodies below are copied verbatim from `17-UI-SPEC.md` Component
Specifications §1, which is the approved contract:

```
interface DriftReportEntry {
  agentId: string
  agentName: string
  date: string
  status: 'NO_USUAL_SHIFT' | 'HONOURED' | 'DRIFTED'
  usualStartTime: string | null
  actualStartTime: string
  deltaMinutes: number | null
}
interface DriftSummary {
  workingAgentDays: number
  noUsualShiftCount: number
  honouredCount: number
  driftedCount: number
}
interface ShiftPopularityEntry {
  templateName: string
  agentCount: number
}
interface DriftReport {
  entries: DriftReportEntry[]
  summary: DriftSummary
  popularity: ShiftPopularityEntry[]
}
```

`ScheduleDetail` gains `driftReport: DriftReport | null`, beside its existing
`preferenceReport: PreferenceReport | null` at line 479.

**`ConstraintWeightsData` is declared today as `{ [key: string]: Score }` — a pure index signature
(client.ts line 379). A plain-number field cannot be added to it as written; TypeScript rejects a
`number` member against a `Score` index type.** Widen the index signature to
`{ [key: string]: Score | number }`. The existing `(weights as Record<string, Score>)[key]` cast on
`ConstraintWeightsPage.tsx` line 99 keeps working for every score row, and the tolerance band is read
and written through its own explicitly-typed path. This is the minimum change that admits the new
field; do not restructure the interface further.

New config keys on `ConstraintWeightsData`: `consistentStartWeight` (Score),
`consistencyToleranceMinutes` (number), `preferredStartShiftModeWeight` (Score).

Shipped default values for the two Score rows come from plan 17-04's `17-BENCHMARK.md` and its V49
migration — read them from there, do not invent them. The tolerance-band default is 60.
</interfaces>

## Flagged assumptions (UI-SPEC dismissals — surfaced, never silently dropped)

`17-UI-SPEC.md`'s `## UI Considerations` dismissed seven state categories across this plan's three
elements. Each is carried here as an explicit planner assumption rather than dropped:

- **E1 (drift main table) / overflow — dismissed.** Not applicable: the table has no fixed-width
  column (unlike the roster's 90px tile); agent names, dates, times and signed integers are short
  bounded strings.
- **E1 / long-text — dismissed.** Not applicable: every cell is a computed value already rendered
  untruncated elsewhere on this page, never operator-authored free text.
- **E2 (popularity section) / partial — dismissed.** Not applicable: a template appears only when at
  least one agent subscribes, so there is no row with a name and no count or a count and no name.

  fixed array and always render; a form has no zero-rows state.
- **E3 / partial — dismissed.** Not applicable: the weights payload is fetched whole per desk; no
  state exists where some fields have loaded and others have not.
- **E3 / overflow — dismissed.** Not applicable: all three new fields are short numeric inputs at the
  existing input width.
- **E3 / zero-one-many — dismissed.** Not applicable: exactly three new rows always render; this is
  not a variable-count collection.
