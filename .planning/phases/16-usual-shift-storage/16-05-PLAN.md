inside each of the seven day tiles in the roster's expanded row, with an inline native `<select>`
for setting and clearing it.

the view was never migrated, costing an entire extra phase. Plan 16-01 already proved the value
reaches the export; this plan closes the roster.

tile line, and the inline picker.
</objective>

<planner_decisions>
- **P-20 — The usual-shift line renders on every desk, including a SLOT-mode desk with no shift
  library.** It is not gated on `schedulingMode`. On such a desk every tile shows State A's en dash
  and the picker offers only the clear option. Gating it would hide stored data on exactly the desk
  an operator piloted back to SLOT — and D-13 keeps that data alive across the switch precisely so
  it is still there when they switch forward again. A stored value that exists but is not displayed
  is the I-1 shape this phase exists to avoid.

- **P-21 — The desk's shift templates are fetched once per page load, not per tile.** One
  `useEffect` calling `shiftTemplates.list(deskId)` alongside the existing roster load, held in page
  state. Seven tiles multiplied by every expanded agent would otherwise be a request storm. Filter
  per weekday at render time from that one array. Refetch it after a successful `setUsualShift` only
  if the response indicates the library changed — it cannot, so do not refetch.

- **P-22 — Weekday names in copy come from the existing `capitalizeDay` helper.** `DeskAgents.tsx`
  already has `capitalizeDay` ("WEDNESDAY" to "Wednesday"), written for exactly this kind of error
  copy. Use it for the D-03 message and the State C tooltip; do not introduce a second weekday
  formatter and do not use `DAY_LABELS`' three-letter form in prose.

- **P-23 — On a 400 the select stays open and the previous selection is restored.** The UI-SPEC
  specifies the inline amber error beneath a still-open select. It does not say what the control
  shows meanwhile. Ruling: revert the control's value to what was stored before the attempt, so the
  operator is never left looking at a selection that was not accepted, and leave the error visible
  until they pick again or click away. This mirrors the hours cell's own inline-error-stays-open
  behaviour without importing its dirty-tracking machinery.
</planner_decisions>

**Control.** `width: '90px'` (matching the neighbouring hours input so the tile's footprint does not
shift), `fontSize: '0.7rem'`, `autoFocus`, and `disabled` while a request is in flight.

**Options, in this exact order.**
1. Always first: an option whose label is an em dash, the word "none", and an em dash — the exact
   string from 16-UI-SPEC.md § Copywriting Contract's clear-selection row. Its value marks the clear
   intent. Selecting it commits with `clearRow: true`.
2. Only when the tile's entry is `STORED_INACTIVE` with reason `RETIRED`: one `disabled` option
   whose label is the stored name followed by "(retired)" in parentheses, set as the control's
   initial value so the control never opens showing a blank selection for a value that IS stored.
   Because it is disabled the operator cannot resubmit it and must actively pick the clear option or
   a live template.
3. Then every template from the page's fetched list where `eraStatus` is `CURRENT` and
   `validWeekdays` includes this weekday, sorted by name ascending. When the tile's entry is `LIVE`
   and its name matches one of these, that option is the control's initial value.

The zero-option case needs no special handling and no extra messaging: with no matching CURRENT
template the control simply renders the clear option (plus the disabled retired option when one
applies). Add a comment saying the 90px column has no room for a message and the operator already
sees the near-empty dropdown.

**Commit.** On the select's native `onChange`, fire the PUT immediately — no Save button, no blur
handler, no dirty-tracking ref. Call `deskAgents.setUsualShift(deskId, agentId, day, ...)` with
either `{ clearRow: true }` or `{ shiftTemplateId }`. On success, replace that agent in the page's
roster state with the returned `DeskAgent` (the endpoint returns the whole updated response) and
close the editor back to the display line. Add a comment recording D-17's reason for this shape: the
neighbouring hours `<input>` needs a blur-triggered save and `cellDirtyRef`/`cellEscapedRef` guards
to work around G-13-DD, where a seeded input collapses its datalist to the single self-matching
option; a closed option list has no equivalent quirk, so none of that machinery is imported here.

until they pick again or click away. This path is defensive rather than primary — the option list
already excludes weekday-invalid templates — so add a comment saying it exists for a stale option
list (for example the template's valid weekdays changed after the picker's data loaded).

**Cancel.** Clicking away with no selection change closes the editor and sends no request. Add no

**No confirmation dialog** anywhere in this task. Clearing is a single-field reversible edit, and
