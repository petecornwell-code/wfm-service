# Phase 16 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Surfaces in scope (exactly two — see `16-CONTEXT.md` "Roster & export surface"):**

1. `frontend/src/pages/DeskAgents.tsx` — the roster's expanded-row day tiles (~line 604) gain a
   **second line** showing the agent's usual shift for that weekday, with inline `<select>` editing
   (D-15, D-16, D-17).
2. `src/main/java/com/wfm/service/DeskAgentExportService.java` (~line 42) — the Excel export gains
   **seven new columns** (D-18). This is a document surface, not a screen: this contract specifies
   header text and cell-value semantics, not visual styling beyond what the existing export already
   does.

**Out of scope:** the per-desk upload template generator's pre-fill and data-validation dropdown
(D-09/D-10 — governed by `16-RESEARCH.md` Pattern 5, a backend document-generation concern with no
independent visual contract), the Shift Library page (Phase 14/15 own it, untouched here), the
consistency constraint and drift report (Phase 17), and any change to the collapsed roster row (D-15
locks this as a tile-internal change only — no new column).

**Density constraint, stated explicitly so it is not silently re-opened:** each day tile is a
90px-wide column inside an already-tight expanded row. Phase 13's G-13-8 already accepted
`Not set (default)` text clipping at this width rather than widen the grid (which would take the row
from ~678px to ~1028px). This phase adds a **second line inside the same tile**, not a wider one —
every size/spacing decision below is chosen to fit that constraint, and clipping (with a `title`
tooltip fallback) is the accepted mechanism here too, not a regression to flag.

## Typography

Inherits the existing Body/Label roles verbatim. **One new size is introduced** — a Meta role,
strictly smaller than Body, because the usual-shift line is subordinate information stacked beneath
the tile's primary hours value inside a fixed 90px column; reusing Body size for a second stacked
line would roughly double each tile's height for information the operator scans, not reads first.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (unchanged — hours value, table cell text) | 14px (0.85rem) | 400 | 1.5 |
| Label (unchanged — weekday header `Mon`/`Tue`/…) | 13px (0.8rem) | 600 | 1.2 |
| Meta (**new this phase** — the usual-shift tile line, all three D-16 states) | 11px (0.7rem) | 400 or 600 (state-dependent, see Component Specifications §1) | 1.2 |
| Display | not used this phase | — | — |

Precedent for an 11px/0.7rem role already exists in this codebase (`ScheduleResults.tsx:502`), so this
is not a novel size introduced from nothing — it is the smallest size already in production use,
applied here to a new element for the first time. No third weight is introduced: every state in
Component Specifications §1 uses only the two already-declared weights (400, 600).

## Color

No new color role is introduced. Every state below reuses an existing token from `14-UI-SPEC.md`'s
established palette.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8f9fa` | Page background (unchanged) |
| Secondary (30%) | `#fff` / `#f3f4f6` | Table/panel surface (unchanged) |
| Accent (10%) | `#3b82f6` | Reserved for: **the usual-shift tile line's template-name text, State B ("set and live") only** — see Component Specifications §1. No other new accent usage this phase. |
| Destructive | `#ef4444` | **Not used by any new element in this phase** — this phase introduces no destructive action (see Copywriting Contract) |

**New/reused semantic roles used this phase:**

| Role | Value | Usage |
|------|-------|-------|
| Warning (amber) | text `#92400e` | D-03's inline 400-rejection error beneath the `<select>` — identical token to the existing hours-cell error (`DeskAgents.tsx:637`), per Phase 13's standing ruling that this phase does not reopen: no `#ef4444` red for new elements |
| Muted / secondary text | `#9ca3af` | State C ("stored-but-not-in-effect") tile text — the identical token already used for the hours cell's "Not set — using schedule default" treatment (`DeskAgents.tsx:90`) |
| Placeholder / lightest gray | `#d1d5db` | **New usage of an existing token:** State A ("never set") tile text — deliberately *lighter* than `#9ca3af`, and deliberately *not* italic, so State A and State C are distinguishable at a glance without reading the text (see Explicit ruling below) |

**Explicit ruling — why State A and State C use two different grays, not one:** D-16 states the
never-set/stored-but-inactive distinction is load-bearing (it is audit I-1's failure shape, and
Phase 17's DRFT-02 depends on it). Using the same muted gray for both would satisfy the letter of
"three states" while failing the reason the distinction exists — an operator scanning the row would
see two visually identical mid-gray blobs and have to read the text to tell them apart. State A
(`#d1d5db`, non-italic, no reason text — nothing is stored) is deliberately flatter/lighter than
State C (`#9ca3af`, italic, name + reason — something is stored but not acting). This mirrors the
existing codebase's own two-tier gray convention: compare the hours cell's "not set" italic-gray
treatment (a *resolved default exists*) against a plain unstyled value (nothing to resolve) — the
same two-tiers-of-absence logic, applied to a case where, unlike hours, no default exists at all.

**Explicit ruling on destructive red (reconfirmed, not re-opened):** Phase 13's ruling — no `#ef4444`
for new elements, route validation/refusal text through warning-amber `#92400e` — still applies.
Phase 16 adds no destructive action: clearing a usual shift via `— none —` is a single-field,
reversible edit (see Copywriting Contract).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Not applicable.** This phase adds no button/CTA. The only entry point is direct-manipulation click-to-edit on the tile's usual-shift line itself (mirrors the existing hours-cell affordance — click the value, edit inline, no "Edit" button) |
| Empty state (State A — never set) | No heading/body block; the tile renders the placeholder glyph `–` with `title="Click to set usual shift"` — the tooltip *is* the guidance, sized for a 90px column, not a full empty-state pattern |
| Stored-but-not-in-effect reason text (State C) | **`{name} · retired`** (D-02 cause — template era retired, no successor) or **`{name} · not worked`** (D-04 cause — weekday excluded in `agent_day_hours`). Both rendered directly on the tile line (not tooltip-only), per D-16's requirement that the reason itself be visible, not just the muted styling |
| Error state (D-03, 400 rejection) | **`{name} doesn't run on {Weekday}.`** — rendered inline beneath the `<select>`, identical placement/styling to the existing hours-cell error (`DeskAgents.tsx:637`). Practically unreachable in normal use since the picker's own option list already excludes weekday-invalid templates (D-03's "does not offer invalid templates at all") — this message is the defensive fallback for a stale option list (e.g. the template's valid weekdays changed after the picker's data loaded), not the primary UX path |
| Clear-selection option (D-17) | **`— none —`** — verbatim, always the first `<option>`, so clearing reads as a deliberate choice rather than a blank/missing value |
| Retired-but-selected option (edge case, see Component Specifications §1) | **`{name} (retired)`** — a disabled `<option>` shown only when the currently stored template has no live successor, so the control never silently shows a blank selection for a value that *is* stored |
| Destructive confirmation | **Not applicable — this phase introduces no destructive action.** Selecting `— none —` is a single-field, easily-reversible edit, identical in kind to the hours cell's own `clearRow`. Per Phase 14's D-12 precedent (no `confirm()` on a non-destructive/reversible action — it trains operators to click through the dialogs that matter), no confirmation dialog is used |

## Component Specifications

### Focal points (one per surface)

| Surface | Primary visual anchor | Why |
|---|---|---|
| Roster day tile | The **existing hours value** (unchanged, Body role, top line) | The usual-shift line is deliberately subordinate — Meta size, beneath the hours line — because contracted hours remain the tile's primary fact; usual shift is a second, smaller-weight fact added to the same tile, not a co-equal one |
| Roster day tile, State B only | The **template-name text itself** (accent blue) | State B is the one state an operator most needs to register at a glance ("this agent has a live usual shift here") — it is the only state that uses the accent color, keeping accent meaningful rather than decorative |
| Excel export | **No new anchor** | A flat document surface — no color, weight, or emphasis convention is introduced; the seven new columns read exactly like the seven day-hours columns beside them |

### 1. Roster day tile — usual-shift line (D-15, D-16, D-17)

**Where:** `frontend/src/pages/DeskAgents.tsx`, inside the existing per-weekday `<div>` at the expanded
row's day-tile block (~line 604), as a sibling `<div>` directly beneath the existing hours `<div>`,
`margin-top: 4px` (spacing token `xs`).

**Data contract this component needs (flag for planner/executor):** the tile must not recompute
D-16's three-state classification client-side from raw fields — that risks a second implementation of
logic the backend already owns (the exact `resolvePreferences`-duplication trap `16-RESEARCH.md`
names as this phase's own anti-pattern). The roster response's per-weekday usual-shift entry should
carry an explicit backend-computed discriminator, e.g.:
```ts
interface UsualShiftEntry {
  status: 'NOT_SET' | 'LIVE' | 'STORED_INACTIVE'
  name: string | null            // null only when status === 'NOT_SET'
  reason: 'RETIRED' | 'NOT_WORKED' | null   // set only when status === 'STORED_INACTIVE'
}
```
mirroring the existing `DayHoursEntry`'s own discriminator shape (`hasRow` / `dayOffType` /
`effectiveHours`). The frontend renders purely off `status` — it does not independently ask "is this
template's era current?" or "does the agent work this day?".

**Three states, exact rendering:**

| State | `status` | Content | Color | Style | Weight | Truncation |
|---|---|---|---|---|---|---|
| A — Never set | `NOT_SET` | `–` (en dash) | `#d1d5db` | normal (not italic) | 400 | n/a (single glyph) |
| B — Set and live | `LIVE` | `{name}` | `#3b82f6` (accent) | normal | 600 | yes, see below |
| C — Stored, not in effect | `STORED_INACTIVE` | `{name} · retired` or `{name} · not worked` (per `reason`) | `#9ca3af` | *italic* | 400 | yes, see below |

All three states: `fontSize: 11px (0.7rem)`, `cursor: pointer`, entire line is the click target that
opens the D-17 editor (mirrors `DayCell`'s existing `onClick`-wraps-the-whole-span pattern).

**Truncation (States B and C, matching the accepted G-13-8 precedent):**
`overflow: hidden; textOverflow: ellipsis; whiteSpace: nowrap; maxWidth: 90px`, with a native `title`
attribute carrying the untruncated string (`title={name}` for State B, `title="{name} — retired, no successor"` /
`title="{name} — not worked on {Weekday}"` for State C's two reasons) so the full value is always
available on hover, exactly as the existing hours-cell clipping already works.

**State A's `title`:** `"Click to set usual shift"` — doubles as the empty-state guidance per the
Copywriting Contract (no separate heading/body block fits a 90px column).

### 2. Roster day tile — inline `<select>` editor (D-17)

**Trigger:** clicking the usual-shift line (any of the three states) replaces it with a native
`<select>`, `width: 90px` (matches the neighbouring hours-cell input's width so the tile's footprint
doesn't shift), `fontSize: 11px (0.7rem)`, `autoFocus` (mirrors the hours cell's existing
`autoFocus` on its `<input>`, `DeskAgents.tsx:616`).

**Options, in order:**
1. `— none —` — always first. Selecting it and committing calls the choke-point endpoint with
   `clearRow: true`.
2. **If the currently stored value has no live successor (State C's retired cause):** one disabled
   `<option>` reading `"{name} (retired)"`, pre-selected as the control's initial value so it never
   opens showing a blank/wrong-looking selection for a value that *is* stored. Because it is
   `disabled`, the operator cannot re-submit it as-is — they must actively pick `— none —` or a live
   template.
3. Every `CURRENT`-era template from the desk's live shift library whose `validWeekdays` includes this
   weekday (per `16-RESEARCH.md`'s already-confirmed data source: `shiftTemplates.list(deskId)`
   filtered client-side on `eraStatus === 'CURRENT' && validWeekdays.includes(weekday)` — no new
   backend endpoint needed), **alphabetical by name, ascending.** If the stored value's name matches
   one of these (the ordinary, non-retired case), that option is pre-selected.

**Commit:** unlike the neighbouring hours `<input>` (which needs a blur-triggered save and a
`cellDirtyRef`/Escape guard to work around a `<datalist>` quirk, per D-17's own stated reason for
*not* reusing that pattern), the `<select>`'s native `onChange` fires the PUT immediately on
selection — no separate Save button, no dirty-tracking guard needed, because a closed option list has
no equivalent quirk to work around. While the request is in flight, the `<select>` is `disabled`.
On success, the control reverts to the appropriate display state (§1). On a 400 (D-03), the inline
amber error (Copywriting Contract) renders beneath the still-open `<select>` so the operator can
immediately pick a different option, mirroring the hours cell's own inline-error-stays-open pattern.

**Cancel:** clicking away with no selection change reverts to the display state with no request sent
(the native `<select>` has no free-text state to escape out of, unlike the hours `<input>` — no custom
`Escape` handler is needed here, unlike that cell's `cellEscapedRef` guard).

**Zero-option edge case:** if the desk's shift library has no `CURRENT` template valid for this
weekday, the `<select>` shows only `— none —` (plus the disabled retired option, if applicable). No
additional messaging is added inside the tile — the 90px column has no room for it, and the operator
already sees the near-empty dropdown when they open it (see UI Considerations, marked backstop).

### 3. Excel export — Usual Shift columns (D-18)

**Where:** `src/main/java/com/wfm/service/DeskAgentExportService.java`, seven new columns inserted
immediately after the existing day-hours group and before `First Name`/`Last Name` (which shift right
by seven — the same index move Phase 13's P-09 already made once for this exact column group).

**Headers (exact literal, via `EnrichedColumnLayout`'s existing `DAY_ORDER` loop and `dayHeader()`
function — no new hardcoded string):**

`Usual Shift Monday`, `Usual Shift Tuesday`, `Usual Shift Wednesday`, `Usual Shift Thursday`,
`Usual Shift Friday`, `Usual Shift Saturday`, `Usual Shift Sunday`

(CONTEXT's D-06 shorthand — "`Usual Shift Mon` … `Usual Shift Sun`" — is illustrative, not the literal
header text; `dayHeader()` already returns the full title-case day name, e.g. `"Monday"`, for the
existing day-hours group, and D-06 explicitly requires reusing that same function, so the new headers
inherit its full-name convention rather than introducing a three-letter abbreviation the day-hours
columns don't use.)

**Cell value contract:** the stored usual-shift's template name (a plain read-through of the row's
real FK — `agentUsualShift.getShiftTemplate().getName()`), or a **blank cell** when no row exists.
This is the **raw stored value**, not the roster's date-resolved, three-state distinction — a retired
era's name still exports as plain text so the file stays a faithful, re-uploadable record of what's on
file (identical value function to D-09's per-desk-template pre-fill, so export and template
generation can share one implementation rather than inventing two). The export does **not** attempt to
represent D-16's "retired" / "not worked" reasons, italics, or muted color — it is a flat grid
document; XCUT-01's "visible" requirement is satisfied by the written value being present as text, not
by reproducing the roster's visual state machine in a spreadsheet cell.

**No new cell styling** — the seven new columns inherit whatever plain/unstyled convention the
existing day-hours columns already use (none, per current code). No color, no bold, no conditional
formatting is introduced.

**No truncation** — unlike the roster tile's 90px constraint, Excel columns auto-size to content; the
full template name is always written in full.

| Category | Status | Verification | Resolution / Reason |

### E2 — Excel export, Usual Shift columns *(document surface, static-content)*

| Category | Status | Verification | Resolution / Reason |
|----------|--------|--------------|---------------------|
