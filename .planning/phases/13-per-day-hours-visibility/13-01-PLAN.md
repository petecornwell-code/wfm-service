<objective>
Tracer slice for Phase 13: make the authoritative `agent_day_hours` model the single source of the
roster's contracted-hours figures, end to end — database rows through `DeskAgentService` and
`DeskAgentResponse` to the rendered roster cell — closing audit finding I-1/F-1 on the read path.

Purpose: today `DeskAgentService.toResponse` computes effective hours from the retired
`Agent.contractedHoursPerDay` scalar falling back to `Desk.defaultContractedHoursPerDay`, and the
upload path nulls that scalar on every re-import. The operator therefore sees a desk-default number
unrelated to the Mon–Sun values they uploaded. This plan proves the corrected read path on one real
path before any expansion work builds on it.

Output: an extended `DeskAgentResponse`, a corrected `DeskAgentService` read path with a
schedule-derived fallback (D-06), a new backend read-path regression suite, and a roster UI that
shows a per-weekday summary and an expandable per-weekday detail row.
</objective>

<planner_decisions>
CONTEXT.md left three items open. They are adopted here as plan-level decisions rather than
re-routed to the user, because CONTEXT.md explicitly delegated them ("Deliberately left to the
researcher/planner to resolve against the code" / "Claude's Discretion").

- **P-01 (adopts 13-RESEARCH.md Assumption A1) — which schedule supplies the D-06 default.** The
  desk's single most-recently-created **persisted** `Schedule`, any status, read via
  `ScheduleRepository.findByTenantIdAndDeskIdOrderByCreatedAtDesc(tenantId, deskId, PageRequest.of(0, 1))`.
  `InMemoryScheduleStore` is deliberately NOT wired in — an unsaved in-progress solve's default will
  not appear on the roster until that schedule is persisted. This is a documented residual gap, not
  a correctness guarantee. When the desk has zero persisted schedules the fallback is the literal
  `new BigDecimal("8.00")`, matching `Schedule`'s own field default (`Schedule.java:69`) — never
  the desk scalar, because D-06 permits exactly one fallback rule to survive.
  Reversibility: costly (per CONTEXT.md D-06) — undoing it reintroduces a second, divergent
  resolution rule a future audit would have to rediscover.

- **P-02 (adopts 13-RESEARCH.md Assumption A3) — the DTO shape.** `DeskAgentResponse` gains a
  `Map<DayOfWeek, DayHoursEntry> dayHours` component built as an `EnumMap` and **always populated
  with all 7 weekdays**, where `DayHoursEntry` is a nested record
  `(boolean hasRow, BigDecimal hours, DayOffType dayOffType, BigDecimal effectiveHours)`. Always-7
  entries means the frontend never has to infer "not set" from a missing key, and `hasRow` carries
  the D-04 distinction explicitly. Reversibility: reversible.

- **P-03 — the meaning of the existing `effectiveContractedHoursPerDay` scalar component.** It is
  recomputed as the **maximum** of the seven resolved weekday effective values (scale 2), i.e. the
  agent's longest contracted weekday / standard working-day length. For a uniform week it is
  byte-identical to today's value, so the two remaining consumers
  (`frontend/src/pages/AgentExceptions.tsx:28` standard-hours default and the export's "Effective
  Contracted Hours Per Day" column) keep their meaning. It must derive from `agent_day_hours` plus
  the schedule default — never from the scalar (13-RESEARCH.md Pitfall 3). The sibling
  `contractedHoursPerDay` component keeps echoing the raw scalar unchanged for backward compat.
  Reversibility: reversible.
</planner_decisions>

<assumption_delta_decision>
**Detected — kind: `pluralization`.** The singular→plural transition (`Agent.contractedHoursPerDay`
scalar → per-weekday `agent_day_hours` rows) landed in Phase 9, but the read side never followed.

- **Noun now primary:** the per-weekday `AgentDayHours` row. "An agent's contracted hours" is a set
  of seven weekday facts, not one number.
- **Decision: `promote`.** This plan promotes `agent_day_hours` to the sole source of every hours
  figure in the roster read path and demotes `Agent.contractedHoursPerDay` to a legacy echo field
  with zero readers in the resolution path.
- **Accepted debt:** five sites still *write* the scalar (`BambooRefreshService:244`,
  `DeskAgentService:143`/`:198`, `DeskAssignmentUploadService:561`, `DeskService:147`) and
  `DeskAgentResponse.contractedHoursPerDay()` still echoes it. Removing it is explicitly deferred
  (Phase 9 D-05, CONTEXT.md Deferred Ideas). What would force the later removal: a new consumer
  reading the echoed scalar, or an operator report that the echoed value misleads.
- **Invariant test (accepted):** `DeskAgentServiceReadPathTest.rosterIgnoresScalar_whenScalarDisagreesWithPerDayRows`
  seeds a scalar that contradicts the stored rows and asserts the response follows the rows. It goes
  red the instant a future change reintroduces the singular assumption in the read path. It is a
  required acceptance criterion of Task 1.
</assumption_delta_decision>
