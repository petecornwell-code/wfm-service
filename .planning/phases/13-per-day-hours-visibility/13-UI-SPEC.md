# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Primary surface:** `frontend/src/pages/DeskAgents.tsx` (roster table + its two existing modals).
**Nature of this phase:** a read-path integration fix plus one new edit affordance layered onto an
existing, dense operator table — not a new page or a new visual language.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — hand-rolled, inline `style={{...}}` objects (React 19, hooks-only) |
| Icon library | none — unicode glyphs only (matches existing `↑`/`↓` sort indicators, `«`/`‹`/`›`/`»` pagination) |
| Font | `system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif` (`frontend/src/index.css:2`) |

**No design system was initialized for this phase — this is a deliberate call, not a skipped step.**
`components.json` is absent and no CSS framework (`tailwind.config.*`, `postcss.config.*`) exists
anywhere in `frontend/`. All 12 existing pages (`DeskAgents.tsx`, `ClientManagement.tsx`,
`DeskManagement.tsx`, etc.) use 100% inline `style` objects against a small shared token set in
`frontend/src/index.css`. `13-RESEARCH.md`'s Standard Stack table verifies this directly
(`frontend/package.json:8` — React 19 with no component library) and states explicitly: *"new UI
must match this convention (inline `style={{...}}` objects, no CSS framework)."* Introducing
shadcn now would mean the phase's ~7 new elements look and behave differently from the 13-column
table they sit inside, on a phase whose own research explicitly scoped itself to avoid new tooling
(see the identical reasoning RESEARCH.md applied to the frontend-test-framework decision, Wave 0
Gaps: *"keeps this phase's blast radius to the stated scope"*). **Every rule below is therefore
written as an extension of the existing hand-rolled token set, not a new one.**

## Component Specifications

*(Extends the template's baseline sections with implementation-level detail the planner needs to
turn D-01–D-08 into a single, unambiguous build — every choice below traces to a CONTEXT.md
decision or a concrete gap CONTEXT.md left to "Claude's discretion.")*

### 1. Collapsed "Hours/Day" cell — summary algorithm (resolves CONTEXT.md's open discretion item)

1. Resolve each of the 7 weekdays' **effective hours** server-side (per D-06: schedule default,
   never the desk default) — `MANDATORY`/`PTO` days resolve to `0.00` per the stored model
   (13-RESEARCH.md Pitfall 2), so they naturally pull into the low end of the range.
2. If `min === max` across all 7 effective values (a uniform week, no labels) → show the single
   value, e.g. `8`.
3. If `min !== max` → show `"{min}-{max}"`, e.g. `4-8` (hyphen, matching the CONTEXT.md mockup's
   literal `6-8` — not an en dash).
4. The collapsed cell **never** shows `MAND`/`PTO` markers — those appear only after expanding,
   keeping the collapsed column scannable (matches the accepted mockup exactly, which shows only a
   number/range in the collapsed state).
5. Clicking anywhere on the collapsed cell (not just a caret) toggles expansion — reuses the file's
   existing click-affordance visual language (`cursor: 'pointer', textDecoration: 'underline
   dotted'`, already used twice in this file for `startEditSpec`/`startEditHours`).

### 2. Expanded row — layout

- Renders as a full-width sub-row directly beneath the agent's row (a second `<tr>` with a single
  `<td colSpan={13}>`, or equivalent) — **not** a new column, honoring D-01's explicit rejection of
  widening the table.
- Contents, top to bottom: (a) the empty-state note from the Copywriting Contract, shown only when
  the agent has zero `AgentDayHours` rows; (b) a 7-column mini-grid, `Mon` through `Sun`, each cell
  per the rendering rules below; (c) the "Set all days to…" bulk action (Section 4).
- Background `#fff` (same as the table surface — reads as part of the same card, not a modal or a
  new visual layer, unlike the file's two existing `position: fixed` overlays which are correctly
  *not* the pattern to copy here — 13-RESEARCH.md's explicit correction to CONTEXT.md).

### 3. Per-day cell — display and edit modes

**Display mode** (not currently being edited), branching in this exact order — this order is
load-bearing per 13-RESEARCH.md Pitfalls 1 and 2:

1. `dayOffType === 'MANDATORY'` → gray badge, text `MAND` (Color: MANDATORY badge role).
2. `dayOffType === 'PTO'` → amber badge, text `PTO` (Color: PTO badge role).
3. Row exists, `dayOffType === null`, `hours === 0.00` → plain text `0`, colored with the
   Explicit-zero role (`#6b7280`) — visually distinct from a normal worked value, per Pitfall 1.
4. Row exists, `dayOffType === null`, `hours > 0` → plain text, the numeric value (e.g. `7.5`),
   default body color, weight 400.
5. No row at all → the resolved default value, styled with the Muted/not-set role (`#9ca3af`,
   italic), with a `title="Not set — using schedule default"` tooltip (matches the file's existing
   tooltip convention at `DeskAgents.tsx:371`, `title={da.pendingPtoDates.join(', ')}`).

Clicking a display-mode cell swaps it into **edit mode** for that single day (mirrors the existing
`editHoursAgentId`/`editSpecAgentId` per-row edit-state pattern — recommend a per-cell state shaped
as `{ agentId, day } | null` rather than a new per-cell state variable per cell).

**Edit mode — the D-03 "type-or-pick combo," concrete control (zero new dependencies):**

A native `<input type="text" list="day-hours-options">` bound to a `<datalist>` containing the
picklist entries `PTO`, `MANDATORY`, `Not set (default)` (`(type a number)` is the input's
`placeholder`, not a selectable option — it cannot be a literal `<option>` since typing anything
resolves it away). This is HTML5's built-in "type or pick" affordance and requires no new
component library, satisfying both D-03's literal requirement and the project's zero-dependency
convention. Resolution on blur/Enter:

| Typed/picked value | Resolves to |
|---|---|
| A number, 0–24, quarter-hour step | `hours = value`, `dayOffType = null` |
| `PTO` (case-insensitive) | `hours = 0.00`, `dayOffType = PTO` |
| `MANDATORY` (case-insensitive) | `hours = 0.00`, `dayOffType = MANDATORY` |
| `Not set (default)`, or the field cleared to empty | Deletes the row entirely (D-04: "selecting a value must be what creates a row" — clearing is the one path that does the opposite, by design) |
| Anything else | Reject client-side; revert the field to the last saved value; show the client-validation copy from the Copywriting Contract inline below the cell |

Saving calls the new per-cell endpoint (D-05) and touches exactly one row. While the request is
in flight, disable the input (no distinct spinner — matches the existing `saveHours`/`saveSpec`
synchronous await-then-rerender convention, which has no loading affordance today). On failure,
revert to the pre-edit display value and show the server error via the existing toast pattern.

### 4. "Set all days to…" bulk action (D-07) — where it lives

The **existing** top-level `Hours/Day` column click-to-edit numeric input (`editHoursAgentId` /
`editHours` / `saveHours`, `DeskAgents.tsx:148-163,352-365`) is **relocated**, not duplicated: it
no longer lives in the collapsed cell (which now only expands/collapses, per Section 1) — it
becomes the explicit, labelled "Set all days to…" control inside the expanded row, positioned
below the 7-day grid exactly as shown in the CONTEXT.md mockup. This resolves the otherwise-open
question of "does clicking the collapsed cell expand the row, or start the old single-value edit?"
in favor of D-01's explicit spec (click expands) without losing the existing fan-out capability
(D-07 requires it survive as an explicit action, not the default one).

- Button reveals: numeric `<input type="number" step="0.25" min="0" max="24">` + an **Apply**
  button + a **Cancel** link, matching the existing `input` + primary-button + secondary-button
  micro-pattern already used for the spec editor (`Save`/`Cancel`, `DeskAgents.tsx:342-343`) —
  standardize on `Apply`/`Cancel` here (not `OK`/`X`) since this is now a distinct, explicitly
  labelled action rather than an inline field toggle.
- Before submitting, check whether **any** of the agent's 7 existing rows carry a non-null
  `dayOffType`. If so, show the destructive-confirmation `confirm()` dialog from the Copywriting
  Contract before calling the endpoint. If none carry a label, submit immediately — no dialog
  (Pitfall 4: checking "rows exist" instead of "rows carry a label" is the wrong trigger and must
  not be used).
- The bulk endpoint's rewrite of all 7 rows must remain a single backend transaction, so a mid-way
  failure never leaves a partial (e.g. 3-of-7) write visible to the operator — call this out to the
  planner as a requirement on the bulk endpoint, not an assumption about existing code.

### 5. Excel export columns (D-02) — visual/format contract for the file itself

Not a browser UI surface, but part of this phase's visual contract since operators open it in
Excel: 7 new Mon–Sun columns, headers sourced from `EnrichedColumnLayout.dayHeader(day)` (already
exists — do not hardcode `"Monday"`..`"Sunday"` strings locally, this is exactly the drift class
I-4 already flagged for specialty headers). Cell values mirror the same branching as Section 3's
display-mode rules 1–5 (a `MANDATORY`/`PTO` cell should render its keyword, not `0`, so the
export/re-upload round-trip in D-02 stays lossless). Column order matches the upload template's
existing day-cell order exactly (Mon→Sun, left to right, immediately following the existing
"Effective Contracted Hours Per Day" column).

### Minimum data shape the frontend needs per weekday

The exact backend DTO field names are open (Phase 9 D-12 deliberately deferred this; 13-RESEARCH.md
Assumption A3 flags it as the planner's call) — but whatever shape is chosen, it must let the
frontend distinguish all 5 states above without a second request per cell:

```
per weekday: {
  hasRow: boolean          // false = "not set", never inferred from hours/type being null
  hours: number | null     // the raw stored value when hasRow is true; null when false
  dayOffType: 'MANDATORY' | 'PTO' | null
  effectiveHours: number   // always present — the resolved display value (D-06), used by
                            // both the collapsed-cell range algorithm and the "not set" tooltip
}
```

| loading | Bulk "Set all days" apply (form/interactive-control) | ✅ covered | Apply button disables during the PUT, mirroring the existing `assigning`/`exporting`/`uploading` boolean-flag pattern already used 4x in this file |

| long-text | Cell values / collapsed summary (form/static-content) | ✅ covered | Every value in this surface is a short, closed-vocabulary token (a number ≤5 chars, or `PTO`/`MANDATORY`/`Not set (default)`) — no operator-authored free text appears anywhere in scope, so truncation/wrapping cannot occur |
