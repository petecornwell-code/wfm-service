<objective>
Add the per-cell edit path that makes `agent_day_hours` directly editable one weekday at a time, and
prove structurally that a single-cell edit cannot disturb the other six weekdays — the property
audit finding I-3 was missing.

Purpose: today the only way to change contracted hours is `DeskAgentService.setContractedHours`,
which deletes all seven rows and recreates them uniformly with `dayOffType` unset, silently wiping
upload-set MANDATORY and PTO labels. D-05 closes that by construction: a new endpoint that touches
exactly one row. The seven-row fan-out survives unchanged as the explicit bulk action (D-07), whose
warning UI is built in plan 13-03.

Output: a single-weekday repository finder, a `setDayHours` service method, a new REST endpoint and
request DTO, a new regression suite, and extensions to the existing contracted-hours suite proving
the bulk response is fresh.
</objective>

<planner_decisions>
- **P-04 (adopts 13-RESEARCH.md Assumption A2) — reject, do not clamp.** The per-cell endpoint
  rejects values below 0 or above 24 with an `IllegalArgumentException`, which
  `GlobalExceptionHandler` (`:29-32`) already maps to a 400. It deliberately does NOT mirror the
  bulk upload parser's silent clamp at 24 (`DeskAssignmentUploadService.java:693-695`): that clamp
  exists because a file import cannot practically reject one bad cell out of thousands, and it
  reports through a warnings channel the single-cell path does not have. 13-UI-SPEC.md's
  Copywriting Contract already commits to the reject wording ("Enter a number from 0 to 24, or
  choose PTO / MANDATORY / Not set (default)."). Reversibility: reversible.

- **P-05 (resolves 13-RESEARCH.md Open Question 1) — two endpoints, not one discriminated endpoint.**
  `PUT .../day-hours/{day}` (one row, D-05) stays structurally distinct from the existing
  `PUT .../contracted-hours` (seven rows, D-07), mirroring how they are distinct in the UI.
  Reversibility: reversible.

- **P-06 (resolves 13-RESEARCH.md Open Question 2) — the per-cell endpoint leaves
  `Agent.contractedHoursPerDay` untouched.** A single-weekday edit has no single scalar value to
  write; guessing one would be a fabrication. The scalar already diverges from reality after every
  upload — this phase's job is to stop reading it, not to keep it artificially in sync with a model
  it cannot represent. Reversibility: reversible.

- **P-07 — the D-07 overwrite warning is computed client-side from data the server already sends.**
  No pre-check endpoint and no extra response field is added. Plan 13-01 already ships
  `dayHours[day].dayOffType` for all seven weekdays, so the frontend can test
  "any weekday carries a non-null label" directly. This satisfies 13-RESEARCH.md Assumption A4's
  requirement that the trigger is "rows carry a label", never "rows exist", without duplicating any
  resolution rule in the browser (the browser reads a fact, it does not re-derive one).
  Reversibility: reversible.
</planner_decisions>
