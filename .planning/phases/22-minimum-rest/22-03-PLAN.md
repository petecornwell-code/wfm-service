<objective>
Give the waiver a home that carries no hours value.

A new `agent_rest_waiver` row keyed `(tenant_id, desk_id, agent_id, date)` with a required reason, plus
the service and the three endpoints that sit beside the Agent Exceptions endpoints an operator already
uses. "Waived" is the presence of the row — nothing more.

Purpose: REST-06's words are "through the existing per-agent exception mechanism", and D-07 reads that
as the Agent Exceptions **surface** rather than the `agent_exception` **row**, because `AgentException`
cannot express a rest-only waiver. Three sites build its lookup map unconditionally on a non-null
`contracted_hours_override`, the column is `NOT NULL` in the schema and re-checked in the service, and
the resolver's own javadoc states the non-nullability as an invariant. A rest-only row with null hours
would make that agent-date's effective hours null, which flows into the `> 0` gate that decides whether
an `AgentShiftAssignment` row exists at all. A separate table relaxes nothing.

This plan is storage and CRUD only. The solver does not read these rows yet — plan 22-05 wires the
problem facts and the shared waived-pair predicate. A table with no reader is inert, which is this
project's established additive-first order.

Output: `AgentRestWaiver`, `AgentRestWaiverRepository`, `RestWaiverService`, `RestWaiverResponse`,
three endpoints on `DeskAgentController`, and `RestWaiverServiceTest`.
</objective>
