<objective>
Put the disclosure in front of the person it is for.

Two additions to `ScheduleResults.tsx`: one span in the existing header row carrying the applied and
unused counts, sourced from the two-second summary poll; and one new tab listing both sections in
full, sourced from the detail response.

Purpose: REST-07's point is that a waiver cannot silently hide a roster problem, and an API-only answer
hides it from exactly the person it is for. The count rides the fast poll deliberately — the detail
payload is roughly 4 MB and must never be polled, so a badge that only updated on the slow path would
silently lag the number it most needs to be honest about.

Output: the badge and the tab, both reading the typed fields the earlier plans landed, introducing no
new design value and no new interaction pattern.
</objective>
