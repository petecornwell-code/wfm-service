<objective>
Widen the proven slice from SHIFT-only to both scheduling modes, which is what D-01 bought.

A SLOT desk has no shift entity and no contiguity constraint, so "a shift" has to be defined there
for the first time: D-02 settles it as the agent's whole assigned span on a business date, first slot
start to last slot end, with the intra-day break gap ignored. This plan adds the second mode-gated
constraint over that definition, sharing one gap implementation with the first.

Purpose: `Desk.schedulingMode` defaults to SLOT, so this is the majority of desks, not an edge. It
is also where the one real trap lives: `exactlyOneBreak` is gated off for SHIFT mode, which makes it
the SLOT-mode break rule, and it requires exactly one gap of exactly the break duration in an agent's
assigned timeslots. A maximal-contiguous-run definition of "shift" would split every compliant SLOT
agent-day in two at its own mandated break and fire the rest constraint on every compliant day on
every SLOT desk. The regression proof for that is Task 2 and it is the point of this plan.

Output: `RestSpan.ofSlots`, `ConstraintWeights.minimumRestSlotWeight`, the
`Minimum rest (slot)` constraint, its registry rows, and `MinimumRestSlotConstraintTest`.
</objective>
