<objective>
Break placement on a shift-scheduled desk becomes a structural attribute of the assigned band rather
than something four emergent constraints discover from assignment gaps; band capacity becomes a real
hard cap; and the previously inert `Break clustering` constraint is given a body that actually
penalises concentration.

Purpose: on the live StubHub (EN) library ~15 Early-shift agents all break 12:00–13:00, leaving that
window's 8–12 FTE demand to Late-shift agents alone — while the constraint that should flag it is
`penalizeConfigurable(a -> 0)`, a documented placeholder, and `breakClusterThresholdPct` is a live
config knob wired to nothing. This plan is where both are fixed, and where Phase 14's classification
table is completed.

Output: six mode-gated constraints with untouched bodies, a real clustering body demonstrated on the
ROADMAP's required contrast fixture, a `bandCapacity` hard constraint, and zero unclassified
constraints.
</objective>

<flagged_assumptions>
The deterministic edge probe left **ENVL-04**, **ENVL-05** and **ENVL-09** unclassified. All three
are surfaced here as explicit planner assumptions rather than dropped or auto-resolved:

- **ENVL-04 (unclassified by the probe).** "An agent's working day on a shift-scheduled desk is
  contiguous, apart from their break" has no data-shape edge because it is a *structural consequence*
  rather than a rule anything evaluates. The planner's assumption: contiguity is not enforced by any
  new constraint. It follows from `shiftEnvelopeCompliance` forbidding every seat outside the
  envelope and from the assigned band's break interval being forbidden inside it — the only legal
  seats are the contiguous run before the break and the contiguous run after it. Task 1 asserts this
  consequence on a solved fixture rather than adding a constraint to restate it. If the assumption is
  wrong, the fix is a gap in `ShiftBandPair.covers`, not a new constraint.
- **ENVL-05 (unclassified by the probe).** "Break placement comes from the shift template rather than
  from the four emergent break constraints" is a claim about which mechanism owns a decision, again
  not a data shape. The planner's assumption: mode-gating the four constraints off is sufficient and
  no shift-mode *variant* of any of them is needed, because in shift mode there is no longer a
  question for them to answer — the break's position is the assigned band's offset. Phase 14's
  classification tagged all four `NEEDS_SHIFT_VARIANT`; this plan reclassifies them `MODE_GATED`
  instead, and Task 1 records that reclassification with its reasoning in both the test and its
  markdown mirror so the change is auditable rather than implicit.
- **ENVL-09 (unclassified by the probe).** The clustering penalty's exact formula and the precise
  meaning of "assigned agents" in its denominator are `15-RESEARCH.md` assumptions A1 and A2, and the
  research explicitly declines to state them as verified facts. The planner's assumptions, stated for
  the record and validated empirically in Task 2 rather than by inspection: the penalty is the linear
  excess of on-break agents over `breakClusterThresholdPct` percent of the timeslot's assigned
  agents; and "assigned agents" means every seated `AgentAssignment` in that timeslot, including
  overflow seats, because that is the population an operator looking at the roster would count. Both
  are locked only after the required contrast fixture demonstrates them, and the fixture is the
  arbiter if it disagrees.
</flagged_assumptions>

<planner_decisions>
- **P-25 — the mode filter is a join and a filter, added above an untouched body.** Each gated
  constraint gains `.join(ScheduleConfig.class)` after its existing joins and, as the very first
  operation after that join, `.filter(... cfg.schedulingMode() == SchedulingMode.SLOT)`. Every
  existing lambda body keeps its logic byte for byte; only its tuple arity grows by one argument.
  `ScheduleConfig` is a `@ProblemFactProperty` singleton — exactly one row per solve — so the join
  costs nothing next to the `AgentDayConfig` join these constraints already carry. A filter added
  after a `groupBy` that has already discarded information can silently narrow the slot-mode result
  set; a body edit can leak a shift-mode change into slot-mode desks. Neither is permitted here.
- **P-26 — the two `OPEN_RESOLVE_IN_PHASE_15` preference constraints are gated off for shift desks
  and reclassified `MODE_GATED`.** In shift mode the start comes from the library and the break comes
  from the assigned band, so both constraints would tune against a signal the operator no longer
  controls per-slot. `research/ARCHITECTURE.md` § 1 reaches the same conclusion. Phase 17's CONS-05
  makes `AgentPreference.preferredStartTime` the tiebreak between two shifts the consistency
  constraint scores equally — that is a *new* use of the preference at shift granularity, not a
  reason to leave the per-slot constraints on.
- **P-27 — `PHASE_15_OWNER` is retained verbatim as the recorded resolver.** The constant still reads
  the phase's former name, and `14-VERIFICATION.md` item 21 asserts it matches its markdown mirror.
  Do not rename it and do not delete it. Reclassify the two rows to `MODE_GATED` while keeping
  `PHASE_15_OWNER` as their `owner` value — the `Entry` record permits an owner on any classification
  and only *requires* one on `OPEN_RESOLVE_IN_PHASE_15` rows — so the constant stays referenced, its
  string stays byte-identical to the mirror, and the verified claim stays true. Update the markdown
  mirror's two rows in the **same commit**.
- **P-28 — `bandCapacity` is a new hard constraint with its own weight column**, not an extension of
  an existing one. D-03 makes capacity a hard cap only when set, and every constraint in this provider
  is weight-driven so hard-vs-soft stays a per-desk configuration row rather than a code decision.
- **P-29 — the D-03 refusal reuses plan 15-01's predicate, it does not re-derive it.**
  `runPreSolveValidation` calls the same capacity-shortfall method `ShiftLibraryValidationService`
  already exposes to the report. One implementation, two callers — the exact discipline Phase 14's
  D-08 established and which UAT confirmed held (the report named four uncovered windows and the
  refusal named the same four verbatim).
</planner_decisions>
