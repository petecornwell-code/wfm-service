  <read_first>N/A — new AWS resource creation via CLI. AWS CLI must be configured (Plan 01 prerequisite).</read_first>

  <action>
Run all three commands below in sequence. Each command must exit 0 before running the next.

**Command 1 — Create the S3 bucket:**
```bash
aws s3api create-bucket \
  --bucket wfm-terraform-state \
  --region eu-west-2 \
  --create-bucket-configuration LocationConstraint=eu-west-2
```

Expected output:
```json
{
    "Location": "http://wfm-terraform-state.s3.amazonaws.com/"
}
```

IMPORTANT: The `--create-bucket-configuration LocationConstraint=eu-west-2` flag is MANDATORY for eu-west-2. Omitting it causes an `IllegalLocationConstraintException` error because AWS treats `us-east-1` as the default and rejects any other region without an explicit LocationConstraint.

**Command 2 — Enable versioning** (required so Terraform state history is preserved):
```bash
aws s3api put-bucket-versioning \
  --bucket wfm-terraform-state \
  --versioning-configuration Status=Enabled
```

This command exits silently (no output) on success.

**Command 3 — Enable server-side encryption** (required by BOOT-01):
```bash
aws s3api put-bucket-encryption \
  --bucket wfm-terraform-state \
  --server-side-encryption-configuration '{
    "Rules": [{
      "ApplyServerSideEncryptionByDefault": {
        "SSEAlgorithm": "AES256"
      }
    }]
  }'
```

This command also exits silently on success.

If `create-bucket` fails with `BucketAlreadyOwnedByYou`, the bucket already exists in your account — this is fine. Proceed to the versioning and encryption commands to ensure those settings are applied.

If `create-bucket` fails with `BucketAlreadyExists`, the name is taken by another AWS account — this is unlikely for a project-specific name like `wfm-terraform-state` but would require choosing a different name (contact Pete to decide).

  <name>Task 2: Create DynamoDB lock table (BOOT-02)</name>
  <read_first>N/A — new AWS resource creation via CLI.</read_first>
  <files></files>
  <action>
Run the following single command to create the DynamoDB table:

```bash
aws dynamodb create-table \
  --table-name wfm-terraform-locks \
  --attribute-definitions AttributeName=LockID,AttributeType=S \
  --key-schema AttributeName=LockID,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST \
  --region eu-west-2
```

The key parameters explained:
- `--table-name wfm-terraform-locks` — must match the `dynamodb_table` value you will set in `main.tf`
- `AttributeName=LockID,AttributeType=S` — `LockID` is the attribute name Terraform expects; `S` means String type
- `KeyType=HASH` — makes `LockID` the partition key (required by Terraform's locking protocol)
- `--billing-mode PAY_PER_REQUEST` — no capacity planning needed; you only pay per operation, ideal for infrequent Terraform runs

Expected output (an excerpt of the full JSON):
```json
{
    "TableDescription": {
        "TableName": "wfm-terraform-locks",
        "TableStatus": "CREATING",
        ...
    }
}
```

The status will be `CREATING` immediately. Wait ~10-15 seconds, then verify it reaches `ACTIVE`:

```bash
aws dynamodb describe-table \
  --table-name wfm-terraform-locks \
  --region eu-west-2 \
  --query 'Table.TableStatus' \
  --output text
```

Expected: `ACTIVE`

If the command fails with `ResourceInUseException`, the table already exists — run the describe-table command above to confirm it has the correct configuration and proceed.

The `-migrate-state` flag is needed because the backend block previously existed (even as empty), so Terraform has a record of a prior initialization. This flag tells Terraform to copy any existing local state to the new S3 backend. If there is no local state to migrate, it is harmless.
