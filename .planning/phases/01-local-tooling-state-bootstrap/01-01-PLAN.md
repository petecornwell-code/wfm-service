<task type="checkpoint:human-action">
  <name>Task 2: Create IAM admin user in AWS Console (TOOL-02 prerequisite)</name>
  <read_first>N/A — AWS Console navigation. No local files involved.</read_first>
  <action>
You must create a non-root IAM user in the AWS Console. AWS explicitly prohibits using root account access keys — root credentials have unrestricted account access including billing and account deletion.

Follow these steps exactly:

**Step 1 — Sign in to AWS Console**
Open https://console.aws.amazon.com in your browser and sign in with your root account credentials (the email + password you used when creating the account).

**Step 2 — Navigate to IAM**
In the search bar at the top of the console, type `IAM` and click the IAM result. You are now in the Identity and Access Management console.

**Step 3 — Create the user**
1. In the left sidebar, click **Users**
2. Click the orange **Create user** button (top-right)
3. User name: type `pete-admin`
4. Leave "Provide user access to the AWS Management Console" UNCHECKED (this user is for CLI only)
5. Click **Next**

**Step 4 — Attach permissions**
1. Select **Attach policies directly**
2. In the search box, type `AdministratorAccess`
3. Check the box next to **AdministratorAccess** (the AWS managed policy — make sure it says "AWS managed policy")
4. Click **Next**
5. Click **Create user**

**Step 5 — Create access keys**
1. You should now be on the user detail page for `pete-admin`. If not, click **Users** in the sidebar and click `pete-admin`.
2. Click the **Security credentials** tab
3. Scroll down to the **Access keys** section
4. Click **Create access key**
5. Use case: select **Command Line Interface (CLI)**
6. Check the acknowledgement checkbox at the bottom
7. Click **Next**
8. Description tag (optional): type `bootstrap` — this helps you remember what this key is for
9. Click **Create access key**

**Step 6 — Save the credentials (CRITICAL — shown once only)**
You will see two values:
- **Access key ID**: starts with `AKIA...` (about 20 characters)
- **Secret access key**: a long string of random characters

**Copy both values somewhere safe right now** — a password manager, a secure note, or a temporary text file. The secret access key is NEVER shown again after you close this page. If you close without copying it, you must delete this key and create a new one.

You can also click **Download .csv file** to save both values to a file. If you do, delete this file after completing Task 3 below.
  </action>
  <resume-signal>Type "done" when you have both the Access Key ID and Secret Access Key saved securely.</resume-signal>
  <acceptance_criteria>
- IAM user `pete-admin` exists in the AWS Console (IAM → Users shows the user)
- AdministratorAccess policy is attached to the user
- You have both the Access Key ID (starts with AKIA) and Secret Access Key saved
  </acceptance_criteria>
  <done>IAM user created with AdministratorAccess and access keys saved.</done>
</task>

<task type="auto">
  <name>Task 3: Configure AWS CLI credentials (TOOL-02)</name>
  <read_first>N/A — configures ~/.aws/credentials and ~/.aws/config. You need the Access Key ID and Secret Access Key from Task 2.</read_first>
  <files>~/.aws/credentials, ~/.aws/config</files>
  <action>
Run `aws configure` in your terminal. It will prompt you for four values — enter them as shown:

```bash
aws configure
```

The prompts and correct responses:
```
AWS Access Key ID [None]: <paste your AKIA... key here>
AWS Secret Access Key [None]: <paste your secret key here>
Default region name [None]: eu-west-2
Default output format [None]: json
```

Press Enter after each value. The command exits silently after the last entry — no confirmation message is normal.

This writes two files:
- `~/.aws/credentials` — stores the access key ID and secret
- `~/.aws/config` — stores the region and output format

Now verify the credentials work by calling the AWS STS (Security Token Service) API:

```bash
aws sts get-caller-identity
```

Expected output (your Account ID and UserId will differ):
```json
{
    "UserId": "AIDA...",
    "Account": "123456789012",
    "Arn": "arn:aws:iam::123456789012:user/pete-admin"
}
```

If you see `AccessDenied` or `InvalidClientTokenId`, the credentials were entered incorrectly — run `aws configure` again and re-enter them carefully.

If you see a response where Arn ends in `:root` instead of `:user/pete-admin`, you accidentally used root credentials. Go back to Task 2 and create the IAM user access keys.
  </action>
  <verify>
    <automated>aws sts get-caller-identity</automated>
  </verify>
  <acceptance_criteria>
- `aws sts get-caller-identity` exits with code 0
- Output is valid JSON containing the keys `UserId`, `Account`, and `Arn`
- The `Arn` field ends with `:user/pete-admin` (not `:root`)
- `~/.aws/credentials` exists: `cat ~/.aws/credentials` shows a `[default]` section with `aws_access_key_id` and `aws_secret_access_key`
- `~/.aws/config` exists: `cat ~/.aws/config` shows `region = eu-west-2` and `output = json`
  </acceptance_criteria>
  <done>AWS CLI is authenticated; `aws sts get-caller-identity` returns the pete-admin IAM user for the target account.</done>
