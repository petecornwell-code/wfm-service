<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API (controller) | HTTP requests with `X-Tenant-ID` header crossing into Spring controllers; tenant resolution via TenantContext |
| Service → Database (JPA) | Tenant-scoped writes/reads — all repository methods used here are explicitly tenant-scoped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01-01 | Tampering | JobTitleConfig writes via repository | mitigate | All read methods on JobTitleConfigRepository require tenantId (findByTenantId, findByTenantIdAndJobTitle, findByIdAndTenantId, findByTenantIdAndNonSchedulableTrue). No findAll exposed to service callers in Phase 5. |
| T-05-01-02 | Information Disclosure | BambooSyncEvent.error_message | mitigate | error_message is free text; downstream caller (Plan 02) MUST avoid logging raw BambooHR API key/server URL. Document this constraint in Plan 02's HttpBambooHRClient task; for this plan, the entity column accepts the string as-is (a value-level redaction would be in the writer, not the storage). |
| T-05-01-03 | Elevation of Privilege | AgentEligibilityService bypass | mitigate | Method takes tenantId as parameter (not from a shared static). Callers (SolverService, DeskAssignmentUploadService, ClientManagementService) all resolve tenantId from TenantContext at request boundary. |
| T-05-01-04 | Spoofing | Agent.employmentType direct write | accept | Field is BambooHR-sourced and only mutated by BambooRefreshService inside the existing tenant-scoped refresh transaction. No public API endpoint mutates it directly in this phase. |
| T-05-01-05 | Denial of Service | Unbounded bamboo_sync_event growth | accept | Append-only event log; index supports O(log n) "latest event" query. Future cleanup is operational, not a Phase 5 concern. ASVS L1 does not require retention enforcement at this scale. |
| T-05-01-06 | Information Disclosure | GlobalExceptionHandler error message echo | mitigate | The 503 response surfaces ex.getMessage() — BambooHRRateLimitedException's message is constructed in Plan 02 with `"BambooHR is rate-limiting requests. Retry in N seconds."` — no API key or URL leakage. |
</threat_model>
