## Spacing Scale

Declared values (all multiples of 4, expressed in rem units consistent with codebase):

| Token | Value | Rem Equiv | Usage |
|-------|-------|-----------|-------|
| xs | 4px | 0.25rem | Icon gaps, tight inline spacing (e.g. badge–text gap) |
| sm | 8px | 0.5rem | Compact element spacing, button gaps in action rows |
| md | 16px | 1rem | Default element spacing, margins between form rows |
| lg | 24px | 1.5rem | Section padding (modal inner padding, card padding) |
| xl | 32px | 2rem | Main content padding (`.main-content` uses `padding: 2rem`) |
| 2xl | 48px | 3rem | Major section breaks between Configuration page sections |
| 3xl | 64px | 4rem | Not used in this phase |

**Exceptions:**
- Touch targets for inline action buttons in table rows: minimum 32px height achieved via
  `padding: 0 0.5rem; min-height: 32px` (xs vertical + sm horizontal = tokens xs and sm).
  32px = 8×4, grid-aligned.
- Modal inner padding: lg (1.5rem / 24px) matching existing Assign Modal at `DeskAgents.tsx:384`.
- Badge inline padding: xs top/bottom and sm left/right — `padding: 0.25rem 0.5rem` (4px 8px).
  Use the xs and sm token names when referencing in code comments; avoid raw decimal fractions.

**New semantic colors for Phase 5 (within existing palette — no new hex values):**

| Use Case | Color | Rationale |
|----------|-------|-----------|
| Pending PTO badge background | #fef9c3 (amber-50 equivalent; see note below) | Distinguishes "informational pending" from the blue action accent |
| Pending PTO badge text | #92400e (amber-800 equivalent) | Accessible contrast on amber-50 |
| Non-schedulable toggle (checked state) | #ef4444 (existing destructive red) | Non-schedulable is a restrictive/warning state |
| Sync status — success | #16a34a (existing success green) | Consistent with toast success |
| Sync status — error/rate-limit | #dc2626 (existing error red) | Consistent with toast error |
| Sync status — unknown/never synced | #6b7280 (existing muted) | Neutral placeholder |

**Note on amber badge:** The codebase does not currently use amber. The closest existing color to
"pending/informational" is the green info surface (`#f0fdf4`), which is already used for upload
panels. To keep the PTO badge visually distinct from both green (success/upload) and red
(destructive), amber-50/800 is the standard semantic choice. These two hex values are the only new
additions to the palette. Both pass WCAG AA at ≥ 4.5:1 contrast ratio for normal text.

## Interaction Contracts

### 1. DeskAgents.tsx — Employment Type Filter

**Primary focal point:** The employment-type filter dropdown and the PTO badge column draw the operator's eye first.

**Placement:** Add a `<select>` control to the existing controls bar (line 253–269), inline with
existing `showActiveOnly` checkbox and button row.

**Options:**
```
All          (value: '')       — default
Full-time    (value: 'FULL_TIME')
Part-time    (value: 'PART_TIME')
```

**Behaviour:** Client-side filter applied to `filteredAgents` (line 227). The employment type
filter is composed with the existing `showActiveOnly` filter — both apply independently.

**Filter expression:**
```
empTypeFilter === '' || da.employmentType === empTypeFilter
```

**State variable:** `const [empTypeFilter, setEmpTypeFilter] = useState('')`

**Resets:** Filter resets to `''` (All) on `loadAgents()` is NOT required — the filter is a
display preference and should persist while the user is on the page.

### 2. DeskAgents.tsx — Employment Type Column

**Placement:** New `<th>` inserted after the "Job Title" column header (currently at line 292).
Column header text: `Emp Type`

**Cell value:** `da.employmentType === 'FULL_TIME' ? 'Full-time' : 'Part-time'`

### 3. DeskAgents.tsx — Pending PTO Badge

**Placement:** In the agent row's Actions `<td>` (line 359), rendered before the "Prefs" link,
on its own line above the action buttons — OR as a dedicated column. Recommended: a dedicated
`<td>` column placed between "Last Refreshed" and "Actions" to keep the Actions cell clean.

**Column header:** `PTO`

**Cell content (when `da.pendingPtoCount > 0`):**
```tsx
<span
  title={da.pendingPtoDates.join(', ')}
  style={{
    display: 'inline-block',
    background: '#fef9c3',
    color: '#92400e',
    padding: '0.25rem 0.5rem',  // xs (4px) top/bottom, sm (8px) left/right
    borderRadius: '4px',
    fontSize: '0.85rem',
    fontWeight: 400,
    cursor: 'default',
    whiteSpace: 'nowrap',
  }}
>
  {da.pendingPtoCount} pending PTO
</span>
```

**When `da.pendingPtoCount === 0` or field is absent:** Render `—` (em dash, plain text).

**Tooltip content:** Comma-separated ISO dates from `da.pendingPtoDates`, e.g.
`"2026-06-10, 2026-06-11, 2026-06-12"`. Native `title` attribute is sufficient — no
custom tooltip component is introduced.

### 4. ClientManagement.tsx — Upload Result Modal

**Primary focal point:** The "N assigned / M skipped" summary line is the first element the operator sees on modal open; skipped rows table appears immediately below when M > 0.

**Trigger:** Replace the `showToast(...)` call at line 162 with `setUploadResult(result)`.
Keep the existing `fileInputRef.current.value = ''` reset.

**State variable:**
```tsx
const [uploadResult, setUploadResult] = useState<DeskAssignmentUploadResult | null>(null)
```

**Modal opens** immediately after the server returns a successful response (even if
`skippedCount > 0`). Error responses (HTTP 4xx/5xx) continue to show a toast — no modal for errors.

**Modal structure (600px wide, max-height 80vh, scrollable):**

```
┌──────────────────────────────────────────────────────────────┐
│  Upload Results                                              │
│                                                              │
│  ✓ N assigned   (bold, 1.1rem)                              │
│  ✗ M skipped    (shown only when skippedCount > 0)          │
│                                                              │
│  [Skipped rows — expandable section, shown when M > 0]       │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ Row   BambooHR ID   Name            Reason           │   │
│  │  2    12345         Jane Smith      ID not found      │   │
│  │  7    —             —               Non-schedulable   │   │
│  └──────────────────────────────────────────────────────┘   │
│  (scrollable up to ~300px max-height)                        │
│                                                              │
│                 [Download skipped as CSV]  [Close]           │
└──────────────────────────────────────────────────────────────┘
```

**Summary line copy:**
- Assigned: `{N} assigned` (green — `#16a34a`)
- Skipped: `{M} skipped` (red — `#dc2626`; omit this line entirely when M === 0)

**Skipped rows table:** Rendered unconditionally when `skippedCount > 0`. Not behind a
toggle/expand — skipped rows are the primary information the operator came to see.

**"Download skipped as CSV" button:**
- Class: default (no `.primary`, no `.danger`) — secondary action
- Only rendered when `skippedCount > 0`
- CSV format: header row `Row,BambooHR ID,Name,Reason` + one data row per SkippedRow
- Filename: `skipped-assignments-{timestamp}.csv`
- Implementation: `Blob` + `URL.createObjectURL` (matches existing `handleExportEmployees` pattern
  at ClientManagement.tsx:187–197)

**"Close" button:**
- Class: default (no `.primary`) — closing is not the primary action
- Action: `setUploadResult(null)` — does NOT undo assignments
- Placement: bottom-right, matching existing modal patterns

**Backdrop click:** Does NOT close the modal — operator may need to read the result carefully.
Only the Close button dismisses.

**Refresh after close:** If `viewDeskId` is set, call `loadDeskAgents(viewDeskId)` when modal
opens (not on close) to reflect the newly assigned agents immediately.

### 5. Configuration.tsx — Non-Schedulable Job Titles Section

**Primary focal point:** The checkbox list is the primary interaction surface; the description text above orients the operator before they toggle any row.

**Placement:** New `<section>` element appended after the closing `</div>` of the existing
BambooHR config block (after line 84), inside the outer `<div className="main-content">`.

**Section heading:** `<h2>Non-Schedulable Job Titles</h2>` at font-size 1.1rem, font-weight 600
(matches ClientManagement.tsx `h2` at line 429).

**Container:** `<div style={{ marginTop: '2rem', maxWidth: '500px' }}>` — same width cap as
existing config form.

**Description text (static):**
```
Agents with these job titles are excluded from schedule solving and cannot be assigned to a desk.
```
Font: 0.85rem, weight: 400, color: #6b7280, margin-bottom: 0.75rem.

**Loading state:** `<p>Loading job titles...</p>` while fetching.

**Empty state:** `<p style={{ color: '#6b7280' }}>No job titles synced yet. Run a BambooHR refresh to populate this list.</p>`

**Checkbox list row (one per JobTitleConfig):**
```tsx
<label style={{ display: 'flex', alignItems: 'center', gap: '0.5rem',
                padding: '0.25rem 0.5rem', borderBottom: '1px solid #f3f4f6',
                cursor: 'pointer', fontWeight: 400 }}>
  <input
    type="checkbox"
    checked={row.nonSchedulable}
    onChange={() => handleToggle(row.id, !row.nonSchedulable)}
  />
  <span>{row.jobTitle}</span>
  {row.nonSchedulable && (
    <span style={{ fontSize: '0.85rem', color: '#ef4444', marginLeft: 'auto', fontWeight: 400 }}>
      Non-schedulable
    </span>
  )}
</label>
```

Note: row padding uses xs (0.25rem) top/bottom and sm (0.5rem) left/right, matching the spacing
token scale. The non-schedulable indicator uses 0.85rem (small/secondary size from the typography
table) at weight 400.

**Interaction:** Each checkbox toggle fires a PATCH to the backend immediately (optimistic update
in UI, revert on error). No "Save" button — individual toggles are instant.

**Error handling:** On PATCH failure, show toast: `"Failed to update job title — please try again"`
and revert the checkbox to its previous state.

### 6. Configuration.tsx — BambooHR Sync Status Card

**Primary focal point:** The status field ("Success" / "Failed") and the "Last sync" timestamp are the first values the operator scans; error details appear below when present.

**Placement:** New `<section>` element appended after the Non-Schedulable Job Titles section.

**Section heading:** `<h2>BambooHR Sync Status</h2>` at font-size 1.1rem, font-weight 600.

**Container:**
```tsx
<div style={{
  marginTop: '2rem',
  padding: '1rem',
  background: '#f9fafb',
  borderRadius: '6px',
  border: '1px solid #e5e7eb',
  maxWidth: '600px',
}}>
```

**Content layout (horizontal flex, wrapping):**
```
Last sync:   2026-05-11 14:32:07   Status: Success ✓   Agents synced: 28   PTO records: 14
```
Or on error:
```
Last sync:   2026-05-11 14:32:07   Status: Failed ✗   Error: Rate-limited — retry in 60 seconds
```
Or when never synced:
```
Last sync:   Never   Status: —
```

**Field layout:** Use `<dl>` definition-list pattern with inline `display: grid; grid-template-columns: repeat(auto-fit, minmax(160px, 1fr))`:

| Field | Value | Notes |
|-------|-------|-------|
| Last sync | Formatted timestamp or "Never" | Use `toLocaleString()` |
| Status | "Success" (green #16a34a) / "Failed" (red #dc2626) / "—" (muted) | Colored `<span>` |
| Error message | Free text string from backend | Only shown when status is failed; full message |
| Retry in | "N seconds" | Only shown when `retryAfterSeconds` is present |
| Agents synced | Number | Only shown on success |
| PTO records pulled | Number | Only shown on success |

**Load behaviour:** Fetched on component mount via `GET /api/v1/configuration/bamboohr/sync-status`.
No polling — operator must navigate away and back (or a "Refresh status" button if desired, but
per CONTEXT.md Open Question 2, refresh remains manual; no auto-poll is introduced).

**Loading state:** `<p style={{ color: '#6b7280' }}>Loading sync status...</p>`

**Empty/never-synced state:** Render the card with "Last sync: Never" and all count fields omitted.

## Accessibility Notes

All accessibility requirements met by following existing patterns exactly:

- All interactive elements are natively focusable (`<button>`, `<input>`, `<select>`, `<label>`)
- Checkboxes use `<label>` wrapping to ensure click target includes the text
- Pending PTO tooltip uses native `title` attribute — keyboard users can access via focus+hover
  in most browsers; this is acceptable for a diagnostic field (not a primary interaction)
- Modal backdrop does not intercept keyboard focus — the modal inner div receives focus via
  its first focusable child naturally (no `autoFocus` needed for this pattern; consistent with
  existing modals in `DeskAgents.tsx`)
- Color is not the only differentiator — status text ("Success" / "Failed") accompanies color
- WCAG AA contrast: amber badge (#92400e on #fef9c3) = 7.1:1 — passes AA and AAA
