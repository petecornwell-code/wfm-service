<objective>
Expand the proven tracer slice into the full move the phase goal requires: every legal shift
window is discoverable, every illegal break placement is refused at generation time, and an
agent-day already pinned one slot below the break threshold is rewritten atomically into a
complete contracted shift rather than merely topped up.

Purpose: the tracer proved the architecture on the easy case (an empty agent-day, one window).
The live symptom is the hard case — agents pinned at exactly `breakThresholdSlots - 1` slots with
no break anywhere. Closing that requires enumerating alternatives so the acceptor has something to
choose from, and it requires the move to clear the agent's existing partial day inside the same
composite move, because any intermediate state that adds slots without completing the break gap is
rejected by the HARD `Exactly one break` rule.

Output: fully enumerated `ShiftWindowFinder.findWindows`, an `AtomicShiftMoveFactory` that filters,
rewrites and bounds, and the two unit-test classes that hold both to their contracts.
</objective>

  <action>
With the test file red, expand `AtomicShiftMoveFactory`:

1. Replace the tracer's zero-assignment-only guard with a genuine under-hours filter: for each
   `AgentDayConfig`, count the agent's existing assignments on that date and skip the agent-day
   entirely when that count is greater than or equal to
   `ShiftWindowFinder.requiredWorkSlots(dayConfig)`. Do this filtering before any window search so
   satisfied agents cost nothing per step — `createMoveList` runs every local-search step and
   unfiltered scanning is the documented move-explosion failure mode.

2. Build the candidate seat pool per agent-day from `schedule.getAssignments()` filtered to the
   matching timeslot date, `getAgent()` null (free) or `getAgent()` equal to this agent (seats the
   agent already holds and may keep), and a `requiredSpecialization` the agent holds as primary or
   secondary. Seats held by a different agent are excluded — this phase fills and rewrites, it does
   not displace another agent, per the researcher's staged recommendation.

3. Add a package-private `buildSeatMoves(Agent agent, List<AgentAssignment> currentlyHeld,
   ShiftWindowFinder.ShiftWindow window)` returning `List<AssignSeatMove>`: first an unassign move
   (target agent null) for every seat in `currentlyHeld` that is not also a work seat of the
   window, then an assign move for every work seat of the window not already held by this agent.
   Skipping no-op pairs keeps each composite move minimal while still leaving the agent-day in
   exactly the window's shape. `createMoveList` wraps each returned list with
   `CompositeMove.buildMove`. Exposing this method package-private is what lets the test assert the
   unassign-then-assign shape without depending on `CompositeMove` internals.

4. Establish all-or-nothing validity here, at generation time: only emit a composite move when
   every work seat in the window is currently free or already held by this agent. Never lean on
   `CompositeMove.isMoveDoable`, which is an OR across submoves, and never lean on
   `doMoveOnGenuineVariables`, which silently skips non-doable submoves rather than aborting — a
   partially applied shift is exactly the illegal state this phase exists to avoid.

5. Add `static final int MAX_WINDOWS_PER_AGENT_DAY = 8` and apply it after enumeration: when the
   finder returns more windows than the bound, down-sample deterministically by taking every
   `ceil(size / MAX_WINDOWS_PER_AGENT_DAY)`-th window rather than the first N, so break positions
   spread across the day stay reachable and repeated seeded runs select identically. Log at debug
   the agent-days scanned, agent-days skipped as satisfied, windows found and moves emitted, so the
   throughput symptom described in the research is diagnosable from logs alone. Log only counts,
   agent UUIDs and dates — never agent names, emails or BambooHR IDs.

6. Keep generation strictly read-only against the `Schedule`: no setter is called anywhere in
   `createMoveList` or its helpers. `AssignSeatMove.doMoveOnGenuineVariables` remains the only
   place a planning variable is written.
  </action>
