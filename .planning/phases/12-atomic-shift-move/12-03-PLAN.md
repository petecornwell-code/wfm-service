configuration, a median-and-spread comparison rather than a single before/after solve, and an
operator decision on whether the measured effect clears the threshold.

green solve is therefore not evidence that this phase worked. Controlling for CPU-time variance
with a fixed seed and step-count termination is what makes the comparison mean anything.

harness out of the default suite, `12-BENCHMARK.md` recording the 5x5 evidence, and an operator

1. **Gate it out of the default suite.** Annotate the class with JUnit 5's
   `@EnabledIfSystemProperty(named = "wfm.benchmark", matches = "true")` so `./gradlew test` skips

2. **Checked-in reproduction fixture.** Write a parameterised builder taking
   `(agentCount, incrementMinutes, contractedHours, breakDurationMinutes, breakBlockedHours,
   overallocationHardLimitPct)` and returning a `Schedule`, following the fixture-construction
   style of `BreakAwareConstructionTest` (`spec`, `agent`, `deskAgent`, `timeslot`,
   `computeTimeslotDemandConfigs` helpers, plus `AgentDayConfig` records). Instantiate the
   ROADMAP reproduction case: 11 agents, one day, 08:00-20:00, 15-minute increments (48
   timeslots), 8.00 contracted hours (32 required work slots), 60-minute break (4 break slots),
   1.00 blocked hours, ON_QUARTER_HOUR alignment, `overallocationHardLimitPct` 400. Build 2 FTE of
   demand per timeslot and expand seats to the 400% limit — 8 seats per timeslot, 384 seats total,
   against 11 agents times 32 work slots = 352 fills, so seat headroom is not the binding
   constraint. Total hours needed is 88, matching the ROADMAP evidence table. Build the fixture
   from constants inside the test class so every run starts from bit-identical input.

3. **Two configurations, one difference.** `baselineConfig()` builds a `SolverConfig` with the
   solution/entity classes, the `ScheduleConstraintProvider` score director, a
   `ConstructionHeuristicPhaseConfig`, and a `LocalSearchPhaseConfig` whose move selector is a
   `UnionMoveSelectorConfig` of `ChangeMoveSelectorConfig` and `SwapMoveSelectorConfig` only —
   this reproduces exactly what Timefold auto-builds today when no move selector is declared.
   `withMoveConfig()` is identical except it appends a `MoveListFactoryConfig` whose
   `moveListFactoryClass` is `AtomicShiftMoveFactory.class`. Nothing else may differ between the
   two, or the comparison measures the wrong variable.

4. **Control the variance.** Both configurations call `SolverConfig.withRandomSeed(seed)` with
   seeds 1 through 5, and terminate on step count via `TerminationConfig.withStepCountLimit(2000)`
   — not `withSpentLimit`. If `withStepCountLimit` is unavailable at 1.16.0, fall back to
   `withUnimprovedStepCountLimit` and record which was used in the harness javadoc; either way the
   baseline and with-move runs must use the identical termination setting. Step-count termination
   is a development tool only: leave `SolverService`'s production wall-clock `withSpentLimit`
   configuration completely untouched. If any single run exceeds roughly 90 seconds, lower the step
   budget, apply the new value to both configurations, and record the value used.

5. **Metrics per run.** Define a nested record `RunMetrics(String config, long seed, int hardScore,
   int softScore, BigDecimal hoursAssigned, BigDecimal hoursNeeded, int agentDaysNeedingBreakWithNone,
   int agentDaysAtPinnedWall, long elapsedMillis)`. Compute
   `agentDaysNeedingBreakWithNone` as the count of (agent, date) groups where `effectiveHours`
   strictly exceeds `breakMinShiftHours` and the contiguous-gap count is zero, reusing the same
   `TreeSet`-walk arithmetic as `ScheduleConstraintProvider.getGapLengths` so the metric and the
   constraint agree. Compute `agentDaysAtPinnedWall` as the count of (agent, date) groups holding
   exactly `ShiftWindowFinder.breakThresholdSlots(dayConfig) - 1` assignments — the ROADMAP's
   reported symptom, which should trend to zero.

6. **Output and assertions.** Run all ten solves (5 baseline, 5 with-move) in one test method,
   print a GitHub-flavoured markdown table of every `RunMetrics` row plus a summary row per
   configuration carrying median, min and max for hard score and hours assigned — median and full
   spread, never a mean, because the baseline distribution is bimodal. Assert the one must-pass
   threshold that is deterministically checkable: `agentDaysNeedingBreakWithNone` is zero in all

Emit only aggregate metrics, synthetic fixture identifiers and scores. The harness must never read
