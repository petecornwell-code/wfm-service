<objective>
Make the desk day start operator-reachable without letting it silently break anything that already
exists.

Purpose: Phase 20 made the backend accept any 15-minute boundary, and `DeskManagement.tsx`'s own
in-code comment defers the editable control to this phase. But a reachable control exposes two
gaps the backend does not yet close. Templates are validated only on save, so re-anchoring can
strand a stored row the save path would now reject — on a `00:00` desk `14:00`-`23:00` is valid, and
at a `21:00` anchor its offsets become 1020 -> 120, which the forward-interval test rejects, while
the duration read still returns 540 by wrapping, so nothing visibly breaks. And the save-time
boundary gate is a fixed 15-minute modulus by design, so `21:15` saves and then refuses to generate
on a 30- or 60-minute desk with no warning in between.

Output: a fifth named refusal on `setDayStart`, a strictly non-blocking tiling advisory, and the
response fields the control needs to render its permanent lock honestly.
</objective>
