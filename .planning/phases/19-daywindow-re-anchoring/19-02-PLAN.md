<objective>
Pin today's nine midnight-implicit `DayWindow` implementations as a frozen oracle inside
`DayWindowTest`, and prove the transcription is faithful while the originals are still callable.

Purpose: criterion 3 requires proving the re-anchored functions produce byte-identical output to the
pre-migration implementation. D-04/D-06 mean that implementation stops being callable, so the
comparison has to be against a copy — and the copy has to be pinned *before* the originals are
rewritten, or a transcription error becomes indistinguishable from a migration error.

Output: a `FrozenOracle` nested class and the sweep harness that will carry criterion 3's proof once
plan 19-06 re-points it at the bound instance.
</objective>

  <action>
Criterion 2 removes a throw. Criterion 3 requires byte-identical output against the pre-migration
implementation. Those two are only reconcilable if the set of inputs where they are allowed to
differ is written down, and it has to be written down while the throw is still observable.

Add a `@Nested` class — `ThrowDomainIsPinned` or a name in the file's existing style — declaring the
throw domain as data rather than prose: for `durationMinutes`, the predicate over `(start, end)`
that is true exactly when today's implementation throws; for `plusWithinDay`, the predicate over
`(base, minutes)` that is true exactly when it throws. Express each as a private static predicate
method on the nested class, so plan 19-06 can reference it by name rather than re-deriving it.

Add one test per predicate that sweeps the same full domain Task 1's sweep covers and asserts, at
every point, that the predicate's verdict matches whether the live static actually throws. Assert
the exception type and message at a bounded set of points inside the domain rather than at all of
them, so the sweep stays fast.

Record the expected post-migration value at each point of the `durationMinutes` throw domain
alongside the predicate — the value the anchored composition yields for an interval whose end
precedes its start, which is the crossing-the-anchor duration. Write this as an expected-value
function, not a comment, because plan 19-06 asserts against it.

Explicitly assert the two equal-endpoint cases that are NOT in the throw domain and must not be
confused with it: at a `00:00` anchor, a start equal to the end at any time other than the anchor
gives zero minutes, and a start and end both equal to the anchor gives a full day of minutes,
because a time equal to the anchor in an end position is the end of the business day. These two are
the boundary between "zero-length" and "the whole day" and are the single most likely thing for the
migration to get wrong.

Do not change any existing assertion in this file. Do not touch `DeprecationIsLive` — plan 19-06
owns its inversion.
