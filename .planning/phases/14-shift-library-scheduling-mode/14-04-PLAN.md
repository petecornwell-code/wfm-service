<planner_decisions>
- **P-15 — The validator is a standalone `ShiftLibraryValidationService` with two public methods.**
  CONTEXT.md leaves "standalone service or method on an existing one" to discretion; D-08 fixes only that
  it is *one* implementation with two callers. Standalone is chosen because the two callers live in
  different services (`ShiftTemplateController`'s page and `DeskService`'s switch), and because
  `SolverService` is already 900+ lines and is on the MODE-05 risk surface this phase is scoped to stay
  away from. `validate(deskId)` returns a report and throws nothing; `requireShiftModeReady(deskId)` calls
  `validate` and converts blocking findings into `PreSolveValidationException`. Two entry points, one
  computation — a report and a refusal that structurally cannot disagree.
- **P-16 — Add an unfiltered live-demand repository read rather than unioning template date ranges.**
  14-RESEARCH.md's A4 left this open. `StaffingRequirementRepository` has a paginated
  `findLiveByDesk(tenantId, deskId, Pageable)` and an unpaginated date-ranged
  `findLiveByDeskAndDateRange`. A template's `effective_to` may be null (open-ended), so the union of
  effective ranges is unbounded and the date-ranged variant cannot express it. Add
  `findAllLiveByDesk(long tenantId, UUID deskId)` with an explicit `@Query` following the identical
  `JOIN FETCH ... scheduleId IS NULL` shape, fetching only `sr.timeslot` — the validator never reads
  `sr.specialization`, so fetching it would be waste.
- **P-17 — The report is a plain DTO with four finding lists plus a demand flag.**
  `ShiftLibraryValidationResponse(boolean hasLiveDemand, List<String> uncoveredWindows,
  List<String> misalignedTemplates, List<HoursAdvisory> hoursAdvisories,
  List<String> unsatisfiableWeekdays)`, with `HoursAdvisory` a nested record. Separate lists rather than
  one flat message list, so the UI can route each finding to its designed surface (14-UI-SPEC.md: the
  coverage panel, the per-row advisory glyph) without string-matching.
- **P-18 — `ErrorDetail` field keys (CONTEXT.md Claude's Discretion).** `demand` for the zero-demand
  refusal, `coverage` for each uncovered window (one detail per window, so the UI can render the list),
  `grid` for each misaligned template, `contractedHours` for the single fatal-hours sentence. These keys
  are the machine-readable contract the frontend filters on; the human text lives in `message`.
- **P-19 — Every date and time in every message is ISO-8601 via `LocalDate.toString()` /
  `LocalTime.toString()`.** No `DateTimeFormatter`, no localized formatter, no `Locale` argument
  anywhere in this service. This is what makes the refusal strings stable across environments and
  assertable verbatim in a test, and it is the MODE-03 encoding edge's requirement.
- **P-20 — "Demanded weekday" for the fatal hours case means: some live demand row exists on a date whose
  `DayOfWeek` is that weekday.** A weekday is unsatisfiable when no pair of (a template valid on that
  weekday and effective on at least one demanded date of that weekday, an agent's `AgentDayHours` value
  for that weekday) has equal net duration. A desk with no agent rows at all therefore reports every
  demanded weekday as unsatisfiable — which is correct and blocking, not vacuous.
</planner_decisions>

    `public ShiftLibraryValidationResponse validate(UUID deskId)` — never throws for a validation finding.
    Steps:
    1. Load the desk's templates via `findByTenantIdAndDeskId`.
    2. Load live demand via `findAllLiveByDesk` and keep only rows with `requiredFTEs` greater than zero.
       `hasLiveDemand` is whether that filtered collection is non-empty.
    3. Reduce the filtered demand to DISTINCT windows keyed by the timeslot's (date, startTime, endTime),
       so two specializations demanding the same slot yield one window.
    4. For each distinct window, test every template with the coverage predicate: the template's weekday
       set contains the window date's `DayOfWeek`; `effectiveFrom` is on or before the date and
       `effectiveTo` is null or on or after it (both ends inclusive); the window's start is on or after
       the template's start and the window's end is on or before the template's end; and, when
       `breakDurationMinutes` is greater than zero, the window does not overlap the derived break window
       (overlap meaning window start strictly before break end and window end strictly after break
       start). A window covered by no template is added to `uncoveredWindows` rendered as
       `{date} {startTime}-{endTime}` with every component from `toString()` (P-19). Sort the list by date
       then start time.
    5. Grid re-check (D-02): call `timeslotGeneratorService.getLiveBounds(deskId)`; when present, run each
       template's start, end, and — when the break duration is greater than zero — derived break start and
       break end through the package-private alignment helper `ShiftTemplateService` already declares, and
       add `{name} ({effectiveFrom})` to `misalignedTemplates` for any template with a misaligned value.
       Call that helper; do not write a second copy of the alignment arithmetic. When bounds are absent,
       leave the list empty.
    6. Hours advisories (D-06/D-07): load `agentDayHoursRepository.findByTenantIdAndDeskId` and index the
       `hours` values by `dayOfWeek`. For each template and each weekday in its valid set, if no indexed
       value for that weekday equals the template's net duration, add a `HoursAdvisory` whose `message` is
       14-UI-SPEC.md's advisory sentence with the net hours and weekday substituted. Equality is
       `BigDecimals.normalize(a).compareTo(BigDecimals.normalize(b)) == 0` — never `equals`, which is
       scale-sensitive, and never a tolerance.
    7. Fatal hours (D-06): compute the set of demanded weekdays as the distinct `DayOfWeek` of every
       filtered demand row's date (P-20). For each demanded weekday, search for any pair of a template
       valid on that weekday whose effective range includes at least one demanded date of that weekday and
       an indexed agent hours value for that weekday, with equal net duration. A demanded weekday with no
       such pair goes into `unsatisfiableWeekdays`, ordered Monday-first.
