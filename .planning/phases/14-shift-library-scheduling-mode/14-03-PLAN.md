<planner_decisions>
- **P-10 — The grid check is skipped, not failed, when the desk has no live timeslots.**
  `TimeslotGeneratorService.getLiveBounds(deskId)` returns `Optional.empty()` when a desk has no live
  timeslot rows. D-02 requires template times to land on "the desk's current timeslot grid"; when no grid
  exists there is nothing to land on, and failing the save would make the library unbuildable before a
  schedule period is generated — the same trap D-06 rejects for the hours match. So: bounds present →
  enforce alignment; bounds absent → skip. The mode-switch gate (14-05) refuses on zero live demand
  anyway (D-05), so nothing slips through un-checked into shift mode.
- **P-11 — Retirement reuses the update endpoint; there is no delete endpoint and no retire endpoint.**
  14-UI-SPEC.md §3 states Retire "calls the update endpoint with the new `effective_to`". D-10 makes the
  date range the whole lifecycle mechanism. 14-RESEARCH.md Pattern 2 records that a hard-delete endpoint
  would be presently unguarded because no FK-holding consumer table exists until Phase 15/16 — so adding
  one now creates a guard obligation with nothing to guard, and a destructive action the UI contract
  forbids. `deleteByTenantIdAndDeskId` stays on the repository solely for `DeskService.deleteDesk`'s
  future cascade; no controller exposes deletion.
- **P-12 — Grid-misalignment failures use `PreSolveValidationException` with per-field `ErrorDetail`s.**
  D-08 fixes the error shape for the coverage validator; the grid check is the other half of D-02's
  "reported at definition time" thesis and needs the same per-field detail array so the UI can render the
  message under the offending field (14-UI-SPEC.md §2). `field` is one of `startTime`, `endTime`,
  `breakStartTime`, `breakEndTime`; `message` is the Copywriting Contract's grid sentence with the desk's
  actual increment substituted; `value` is the offending time as ISO-8601. All other rejects
  (blank name, inverted times, break past the envelope, empty weekday set, missing effective_from,
  inverted range) use `IllegalArgumentException` → 400 `VALIDATION_FAILED`, and identity/overlap
  collisions use `ConflictException` → 409 `CONFLICT`, both already wired in `GlobalExceptionHandler`.
- **P-13 — `eraStatus` is computed server-side.** `ShiftTemplateResponse` gains a
  `String eraStatus` component with values `CURRENT`, `UPCOMING`, `PAST`, derived from the row's range
  against `LocalDate.now()`. The non-overlap invariant is enforced in the service, so the era must be
  derived where the invariant lives; a browser-side re-derivation would be a second implementation of an
  invariant only the server can guarantee.
- **P-14 — Ordering is applied in the service, not by a derived repository method name.** The list is
  sorted by `name` ascending then `effectiveFrom` descending in `listShiftTemplates`, using a stable
  comparator, so the order is one readable line rather than a long derived-query method name, and so a
  tie on both keys preserves insertion order between reads.
</planner_decisions>
