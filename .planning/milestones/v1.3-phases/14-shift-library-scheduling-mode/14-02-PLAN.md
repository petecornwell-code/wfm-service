<planner_decisions>
- **P-06 — The classification lives in test scope, not `src/main/java/com/wfm/solver/`.**
  `src/test/java/com/wfm/solver/ScheduleConstraintClassification.java` keeps
  `src/main/java/com/wfm/solver/` byte-identical for the whole phase, which turns MODE-05's "additive,
  not a rewrite" claim from an assertion into a structural fact provable by `git diff --name-only`.
  D-15's requirement that "adding a 20th constraint fails the build until someone classifies it" is fully
  satisfied from test scope — `./gradlew test` fails. Phase 15 consumes the markdown mirror, not the Java
  type, so nothing downstream needs the map on the main classpath.
- **P-07 — The registered set is derived by reflection, twice, never by parsing a count.**
  Derivation 1: `ConstraintWeights.class.getDeclaredFields()` filtered to fields carrying
  `@ConstraintWeight`, collecting the annotation's `value()` — this yields the human-readable constraint
  names, which are exactly the strings `.asConstraint(...)` registers. Derivation 2:
  `ScheduleConstraintProvider.class.getDeclaredMethods()` filtered to methods whose return type is
  `ai.timefold.solver.core.api.score.stream.Constraint` and whose single parameter is a
  `ConstraintFactory` — this yields the builder-method count independently of the weight configuration.
  The test asserts the classification key set equals derivation 1 **and** that its size equals derivation
  2's count. Neither derivation hardcodes a number; a constraint added with no weight still fails.
  Chosen over instantiating a `ConstraintFactory` (no public accessor exposes one outside a solver build,
  and no test under `src/test/java/com/wfm/solver/` loads a Spring context today) and over parsing the
  provider's source text (brittle against formatting).
- **P-08 — The tag vocabulary is a four-constant enum.** `MODE_AGNOSTIC`, `MODE_GATED`,
  `NEEDS_SHIFT_VARIANT`, `OPEN_RESOLVE_IN_PHASE_15`. `MODE_GATED` is deliberately unused today: ROADMAP
  success criterion 5 says the four break constraints "aren't actually mode-gated until Phase 15", so the
  tag exists for Phase 15 to move rows into, and its current emptiness is itself a finding.
- **P-09 — Constraint count is 19, derived not asserted.** RESEARCH confirmed 19 by two independent
  reads and this planner confirmed it a third time (19 `.asConstraint(` literals, 19
  `Constraint`-returning builder methods, 19 `@ConstraintWeight` fields). ARCHITECTURE.md's "18" is stale
  because it predates `minimumStaffing`. The number appears in the markdown mirror as a *reported* count;
  it appears nowhere in the test.
</planner_decisions>
