<planner_decisions>
Decisions this planner made where CONTEXT.md left discretion or RESEARCH.md left the question open.
Executors adopt these verbatim; deviating requires raising it, not silently choosing otherwise.

- **P-01 — Weekday storage (CONTEXT.md Claude's Discretion).** A fixed-position 7-character mask
  column `valid_weekdays CHAR(7) NOT NULL`, index 0 = MONDAY … index 6 = SUNDAY, `'1'` = valid,
  `'0'` = not valid. Chosen over a first-ever `@ElementCollection` (zero precedent in this codebase —
  14-RESEARCH.md Anti-Patterns), over a join table (ceremony for a 7-bit fact), and over a SMALLINT
  bitmask (unreadable in psql). The mask is Monday-first by construction, which is exactly what the
  SHLB-02 ordering rule requires. The entity exposes `Set<DayOfWeek> getValidWeekdays()` /
  `setValidWeekdays(Set<DayOfWeek>)`; the mask string is a storage detail no caller sees.
- **P-02 — `scheduling_mode` column width.** `VARCHAR(10)` in SQL, `length = 10` on the
  `@Enumerated(EnumType.STRING)` column. 14-PATTERNS.md suggested `length = 5` (exact fit for
  `'SHIFT'`); 10 is chosen for headroom on a two-value enum that Phase 15 may extend, at zero cost.
- **P-03 — Migration verification.** `src/test/resources/application-test.yml` sets
  `ddl-auto: create-drop` with `flyway.enabled: false`, so `./gradlew test` derives the H2 schema from
  JPA annotations and **never executes V39**. A broken migration would ship with a green suite. The
  automated criteria therefore assert the SQL source directly, and the plan carries a `<human-check>`
  for actual Flyway application against the dev Postgres.
- **P-04 — Tracer end-to-end proof.** This codebase has no MockMvc or web-layer harness (verified:
  `GlobalExceptionHandlerTest` is a plain instantiation test, and Phase 13 recorded P-17 "no new
  MockMvc harness"). The end-to-end check is a `@DataJpaTest` that `@Import`s the controller *and* the
  service and calls the controller methods directly — controller → service → repository → H2 → DTO,
  every backend layer, no new harness. The frontend leg is proven by `npm run build` plus source
  assertions, since no frontend test framework exists.
- **P-05 — Break input vs. break storage (14-UI-SPEC.md §2).** The operator enters a wall-clock break
  start; `breakOffsetMinutes` is computed client-side immediately before submit. The API and the
  database store the offset only (D-01), and the response carries the derived wall-clock window back.
</planner_decisions>
