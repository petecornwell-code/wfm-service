<planner_decisions>
- **P-26 — No frontend test framework is introduced.** `frontend/package.json` has no `test` script and
  no vitest/jest/testing-library dependency (verified this session); Phase 13 recorded the same decision
  for a comparably sized UI phase. Every automated criterion below is therefore a source assertion or a
  `npm run build` exit code, never "a test asserts". The six purely visual claims are marked `backstop`
  in `must_haves` and route to `human_needed` at verification unless visual evidence is wired — that is
  honest-verifier behaviour, not over-flagging.
- **P-27 — The SHLB-06 advisory is read from the validation report, not from the save response.** The
  save endpoint returns the created or updated template only. After every successful save the page
  refetches `shiftLibrary.validation(deskId)`, which drives both the coverage panel and the per-row
  advisory glyph from one response. This is the concrete UI expression of D-08's one-validator rule and
  it means an advisory that becomes true because of a roster change elsewhere appears on the next page
  load without any save.
- **P-28 — The advisory toast is a second toast, not a second line in the success toast.**
  14-UI-SPEC.md §2 leaves this to the planner. Two toasts because the two facts have different
  lifetimes and different severities: the save succeeded (success), and separately this template matches
  nobody's hours today (amber advisory). Merging them would make a purely advisory sentence read as a
  qualification of the save's success.
- **P-29 — The Desk Management mode cell is plain text, not a badge.** 14-UI-SPEC.md §6 leaves this to
  the planner. Plain text because the gray badge treatment is already spoken for as the `Current` era
  signal on the Shift Library page, and reusing it for an unrelated read-only value would dilute the one
  signal it currently carries.
- **P-30 — The mode toggle is optimistic-with-revert.** Clicking an option immediately reflects the new
  selection and disables both options; on any error the selection snaps back to the server's last known
  value. This is what 14-UI-SPEC.md §5 describes ("the toggle visually snaps back"), and it means the
  page never shows a mode the server did not accept.
</planner_decisions>
