<objective>
Make the operator able to SEE what the report layer has been hiding.

`ScheduleResults.tsx` renders the same agent-day two different ways: the Agent Allocation group
header (:632) uses the authoritative template times, while the Agent Schedule table (:868) renders
`shiftStart`/`shiftEnd`, which the backend computed as min/max over the agent's own seats. That is
why one view reads "Late 12:00-21:00" and the other reads "09:00-21:00" for the same agent on the
same day. Plan 15-10 corrects the backend so the derived values are no longer produced on a shift
desk and adds an explicit divergence surface; this plan consumes both, and adds the two things a
solved-schedule view has never been able to show:

- an envelope breach, rendered as a breach rather than absorbed into a redrawn envelope;
- an hour the shift library deliberately does not reach, rendered as deliberately unstaffed rather
  than silently missing from the grid.

That second item is the visible half of operator ruling OR-1. The ruling accepts that a zero-demand
hour on a shift desk may show genuinely empty cover; it also requires that outcome be visible so
nobody mistakes it for a bug later. Because plan 15-09 suppresses the seat entirely at such an hour,
the column would otherwise simply vanish from the grid, which is exactly the silent outcome the
ruling forbids.

Purpose: close the instrument half of G-15-10 at the surface an operator actually reads.
Output: an Agent Schedule table that reads authoritative shift data, a divergence rendering in both
shift-mode views, and a distinct treatment for hours no envelope reaches.

**Not in this plan:** any change to the slot-mode branch, any change to the Agent Allocation grouping
logic, and any new frontend dependency or test framework — this project deliberately has neither
(Phase 13 P-11), so the type-checking build is the automated gate.
</objective>
