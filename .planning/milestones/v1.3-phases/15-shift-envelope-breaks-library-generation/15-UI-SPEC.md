# Phase 15 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Surfaces in scope (exactly three — see `<scope>`):**

1. `frontend/src/pages/ShiftLibrary.tsx` — the Add/Edit template form's single break offset/duration
   fields become a repeatable **break band editor** (D-01/D-03/D-08).
2. `frontend/src/pages/ShiftLibrary.tsx` — a new **Suggested Library** draft panel (SHLB-07, D-11/D-12).
3. `frontend/src/pages/ScheduleResults.tsx` `AgentAllocationTab` (~line 285) — **shift-grouped
   rendering** for shift-scheduled desks (ENVL-10); slot-scheduled desks render byte-identical to today.

**Out of scope:** roster page, desk management page (beyond the read-only column Phase 14 already
shipped), constraint-weights page, navigation, and any change to slot-scheduled rendering. No
component library, CSS framework, or frontend test framework is introduced — standing project
decision (Phase 13).

**Nature of this phase:** this is a *modification* of the surface Phase 14 specified, not a redesign.
Every token, color, spacing value and copy convention below is inherited from
`14-UI-SPEC.md` unless a row explicitly says "new this phase." Phase 14's file remains the source of
truth for everything on `ShiftLibrary.tsx` this phase does not touch (the template list's other
columns, the Retire flow, the Scheduling Mode toggle, `DeskManagement.tsx`'s mode column).

## Color

Inherited verbatim from `14-UI-SPEC.md`. **No new color role is introduced this phase** — every new
element below reuses an existing token.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8f9fa` | Page background (unchanged) |
| Secondary (30%) | `#fff` / `#f3f4f6` | Panel/table surface; table header rows; **new this phase:** the Agent Allocation shift-group header bar reuses `#f3f4f6` (the exact table-header-row token) |
| Accent (10%) | `#3b82f6` | Reserved for: "Add Shift Template" button, per-row "Save" buttons (template edit **and** the new draft-row save), the Scheduling Mode toggle's selected state, and `input:focus`/`select:focus` outlines. **The new "Suggest a Library" button and the new "+ Add Break Band" button are deliberately plain/outline-weight, not accent** — see Explicit ruling below |
| Destructive | `#ef4444` | **Not used by any new element in this phase** (see ruling) |

**Explicit ruling — accent stays narrow (carried forward from Phase 14's own explicit re-statement of
this rule, extended here since this task asked the identical question):** Phase 15 introduces two new
buttons that could plausibly be styled as primary actions — "Suggest a Library" and "+ Add Break
Band" — and both are deliberately **not** accent-colored. Accent is a scarce visual resource reserved
for the one action per section an operator is most likely to want (per the 60/30/10 discipline); a
page with three accent-blue buttons stops the color meaning anything. "Suggest a Library" sits beside
"Add Shift Template" as an alternative way to populate the library, not a more-important one — plain
button styling (matches the existing "Cancel" treatment: `background: '#fff', border: '1px solid
#d1d5db'`). "+ Add Break Band" is a nested sub-action inside a form that already has its own accent
"Save" button — giving it accent too would create two blue targets in one form.

**Explicit ruling on destructive red (reconfirmed, not re-opened):** Phase 14's ruling — no
`#ef4444` for new elements, route validation/refusal text through warning-amber `#92400e` — still
applies. Phase 15 adds no destructive action (dropping a draft row is even less consequential than
Phase 14's Retire, since the draft was never persisted). The pre-existing red/pink treatment already
on `ScheduleResults.tsx` (violation names, the "Unfilled" row) is untouched by this phase and is not
a "new element" this ruling governs — it predates Phase 15.

**New/carried semantic roles used this phase:**

| Role | Value | Usage |
|------|-------|-------|
| Warning (amber) | bg `#fffbeb`, border `#fde68a`, text `#92400e` | Unchanged usage, **plus new this phase:** the Suggested Library's partial-coverage state (reuses the `CoveragePanel` component verbatim — see Component Specifications §2) and its zero-demand/zero-hours refusal state |
| Neutral badge (gray) | bg `#e5e7eb`, text `#374151` | Unchanged usage (the "Current" era badge), **plus new this phase:** the "Draft" badge on the Suggested Library section heading — reuses the identical token because both are "this is a distinct, non-error state" signals, not a new badge color |
| Muted / secondary text | `#9ca3af` | Unchanged usage, **plus new this phase:** the zero-band empty-state line ("No break bands added…"), the band preview's `· unlimited` suffix, and the "No shift assigned" group-header label in Agent Allocation |
| Border, dashed | `#d1d5db` (existing border-gray token), `border-style: dashed` | **New this phase, structural only — not a new color.** The Suggested Library draft container uses a dashed border in the existing gray to reinforce "not part of the saved list" without inventing a color |

## Component Specifications

### Focal points (one per surface)

Added at checker request (Dimension 2 FLAG) so the executor reads visual priority off a stated rule
rather than inferring it from the colour and spacing sections.

| Surface | Primary visual anchor | Why |
|---|---|---|
| Shift Library page, toolbar | The existing accent **`Add Shift Template`** button | It is the page's one accent element and stays the page's entry action. `Suggest a Library` sits beside it deliberately *un*-accented — a suggestion is an assist, not the primary way to build a library, and giving it accent weight would imply generation is the expected path. |
| Break band editor (inside the template form) | The **band row list** as a block, not any single control | The form already has its own primary action (`Save`); the band list is a field group within it. `+ Add Break Band` is a nested sub-action and stays plain, per the accent-narrow ruling. |
| Suggested Library draft panel | The **dashed container with its `Draft` badge** | The single most important thing an operator must read here is "this is not saved yet." The container edge and badge carry that, ahead of any row content or per-row control. |
| Agent Allocation, shift-scheduled | The **group header bar** (shift name + headcount) | The whole point of ENVL-10 is that a solve is sanity-checkable by eye; the header bar is what makes the grouping legible at a glance, so it outranks the per-agent rows beneath it. |
| Agent Allocation, slot-scheduled | **Unchanged — no focal point is introduced** | Any new anchor on this branch would itself be a regression. |

### 1. Break band editor (replaces Phase 14's single break-offset fields) — D-01, D-03, D-08

**Where:** inside `ShiftLibrary.tsx`'s existing Add/Edit inline form (`renderForm`), replacing the
current "Break start time" + "Break duration (minutes)" field pair.

**Structure:**

- A `Break Bands` sub-label (Label role, 13px/600) above a vertical list of band rows, gap `sm` (8px)
  between rows, contained in a `12px`-padded box matching the form's existing field-group chrome.
- Each band row: `Break start time` (`<input type="time">`, unchanged control type from Phase 14's
  single-field version), `Duration (minutes)` (`<input type="number" min="0">`), `Capacity (optional)`
  (`<input type="number" min="1">`, placeholder `"Unlimited"`, **default blank** — never pre-filled
  with 0 or any number, per D-03's "blank must be the default and must read as deliberate"), and a
  `Remove` button (plain, small, `fontSize: 0.8rem`, matches the existing per-row edit-mode
  Save/Cancel sizing) at the row's end.
- Directly beneath each row: the per-band preview line (Copywriting Contract), muted `#9ca3af`, same
  treatment as Phase 14's single preview line.
- Beneath the band list: `+ Add Break Band` (plain button) appends a new blank band row
  (`{ breakStartTime: '', breakDurationMinutes: '0', capacity: '' }`).
- **Zero bands (valid state, D-08's discretion "yes — zero bands = no break"):** render the muted
  empty-state line in place of the (empty) list, with `+ Add Break Band` still available beneath it.
  This is not an error state and gets no amber/warning chrome — it is Phase 14's already-established
  "no break" affordance, just reached by removing all bands instead of leaving one at zero duration.
- On submit, each band's wall-clock `breakStartTime` is converted to `breakOffsetMinutes` client-side
  immediately before the request (`toMinutes(bandStart) − toMinutes(startTime)`), exactly mirroring
  Phase 14's existing single-field conversion — extended to run once per band, not once per template.

**Grid-misalignment errors (D-02, generalised to any-band per `15-CONTEXT.md` D-02):** each band's
computed start/end is checked against the desk's timeslot grid independently. A misaligned band
renders its inline amber error beneath *that band's own row*, not once for the whole form — an
operator with three bands and one misaligned band must see exactly which one to fix.

**Residual-risk capacity advisory (D-03's "known residual risk, to be surfaced not discovered" —
planner decides the exact mechanism; this is the rendering contract for whichever mechanism is
chosen):** IF the planner implements a save-time advisory for "capacities sum below shift headcount,"
it renders in the **identical shape** already established for SHLB-06's hours-mismatch advisory: a
`⚠` glyph with a native `title` tooltip, warning-amber palette, non-blocking (the save still succeeds,
per the same "advisory on save, blocking only later" pattern D-06 established in Phase 14). No new
visual pattern is invented for this case — reuse the existing glyph-plus-tooltip mechanism, placed
either in the existing "Hours match" column or a new adjacent column; exact column naming is the
planner's call, but the glyph/tooltip/color/non-blocking-toast mechanics are locked by this contract.

### 2. Shift Template list — Break column, now band-aware (extends Phase 14 §1)

The `Break` column must render N bands, not one:

- **Zero bands:** `"No break"` (muted `#9ca3af` text — not a blank cell; a blank cell would read as
  missing data, and this is a deliberate, valid state per Phase 14's own zero-duration-break
  precedent, now expressed as zero rows instead of a zero-duration row).
- **One band:** unchanged from Phase 14 — `{start}–{end} ({duration}m)`, with `· cap {N}` appended
  only when that band's capacity is set (nothing appended when unlimited — the read-only table
  omits the explicit "unlimited" suffix that the editable form's preview line always shows, since a
  table cell repeating "unlimited" on every unset row is noise the codebase's existing
  minimal-chrome convention (the blank "Hours match" cell for a clean row) already argues against).
- **Two-or-more bands:** each band renders on its own line inside the same cell, in offset-ascending
  order, same per-band format as the one-band case (`{start}–{end} ({duration}m)` with `· cap {N}`
  where set). No maximum-row cap is imposed — expected band counts are low (the worked example uses
  two), so no overflow/truncation rule is needed at this scale.

### 3. Suggested Library draft panel (SHLB-07 — D-09, D-10, D-11, D-12)

**Placement:** a new section between the Shift Template list and the Coverage panel, heading
`Suggested Library` (Heading role, 18px/600) with a `Draft` badge (Neutral badge gray token) beside
the heading whenever a draft is present. The section renders nothing (no heading, no panel) before
the operator has ever clicked "Suggest a Library" — it appears on first request, not as a permanent
empty slot.

**Trigger:** `Suggest a Library` (plain button, Color contract ruling above) sits beside `Add Shift
Template` in the page's top toolbar row. Clicking it calls the stateless generation endpoint
(D-11 — no persistence, recomputed on every click). While in flight, the button reads
`"Suggesting..."` and disables, matching the codebase's existing boolean-flag convention
(`assigning`/`exporting`/`uploading`).

**Three possible results, one call:**

1. **Refused (D-12):** zero live demand rows or zero contracted-hours agents. Render the section
   heading (no `Draft` badge — nothing was generated) followed by the amber refusal panel
   (Copywriting Contract), styled identically to the existing zero-demand Coverage-panel state —
   **never an empty draft table.**
2. **Full coverage:** the draft rows render (below) with no additional coverage block — the presence
   of complete draft rows already implies success; no new "✓" sentence is needed beyond what the
   rows themselves show.
3. **Partial coverage (D-12):** the draft rows render, **plus** the identical `CoveragePanel`
   component reused verbatim beneath them, fed the generation response's own uncovered-windows list
   (the same `ErrorDetail` shape SHLB-05 already emits) — this is the concrete meaning of "the panel
   an operator reads after generating is the panel they read after validating." Do not build a second
   uncovered-windows renderer.

**Draft rows:** each generated candidate renders as an **always-editable row** (not gated behind a
click-to-edit toggle, unlike saved templates) — reusing the exact same field set and controls as the
Add/Edit form (Name, Start/End time, the band editor from §1, weekday checkboxes, Effective
from/to), because the whole point of a draft is fast pre-save iteration, not a second read/edit mode
distinction. This is a deliberate, named exception to the saved-template list's
view-then-click-Edit pattern (§2), not an oversight.

- Per row: `Save` (accent — commits this one row through the existing `ShiftTemplateService`
  create/validate path, D-11's "unchanged" requirement; on success the row disappears from the draft
  and appears in the normal Shift Template list below, exactly as a manual "Add Shift Template" save
  would) and `Drop` (plain — removes the row from the in-memory draft only, no request sent).
- A saved-row's own D-02/SHLB-06 errors render through the identical inline/toast mechanism as a
  manual create — no separate draft-specific error path.
- The draft container has a **dashed** `#d1d5db` border (Color contract) to visually separate it from
  the solid-bordered saved-template table, plus the discard-notice line (Copywriting Contract) at the
  top.
- Default field values for a freshly generated row: `Name` = `"Suggested {n}"` (editable, Copywriting
  Contract), `Effective from` = today, `Effective to` = blank (open-ended) — mirroring the manual
  Add form's own defaults, so nothing about a generated row's starting state looks unfamiliar.

**Re-requesting:** clicking `Suggest a Library` again while a draft is present replaces the entire
draft in place (D-11 — stateless, recomputed fresh every time); any unsaved edits to the previous
draft are discarded along with it. No confirmation dialog (same no-`confirm()`-on-non-destructive
rule — nothing generated has ever been persisted, so nothing is "lost" in any sense the guarantees in
this codebase care about; the discard-notice line already sets that expectation).

### 4. Agent Allocation view — shift grouping (ENVL-10)

**API surface this component needs (flag for planner/executor — not this document's to design, but
the UI cannot branch without it):** `ScheduleDetail` must expose a `schedulingMode: 'SLOT' | 'SHIFT'`
field recording the mode the schedule was actually solved under (not a live re-fetch of the desk's
current mode, so a report renders correctly even if the desk's mode changes after this schedule was
accepted — consistent with MODE-04's guarantee). When `schedulingMode === 'SHIFT'`, each
`AgentScheduleEntry` must additionally carry a nullable `shift: { templateName: string; startTime:
string; endTime: string } | null` field. Exact field naming is the planner's call; the two data
points above (a mode signal, plus a per-entry nullable shift descriptor) are the minimum the design
below requires.

**Hard constraint, restated as an implementation instruction:** the existing per-date rendering block
in `AgentAllocationTab` must branch at its top — `if (schedulingMode !== 'SHIFT')`, render the
existing table exactly as it is today, byte-for-byte, no restructuring; `else`, render the grouped
variant below. This mirrors the backend's own mode-gating discipline (filter at the top, body
untouched) applied to the frontend's render logic, for the identical reason: a shift-mode change must
not be able to leak into slot-mode rendering by construction.

**Grouped variant (shift-scheduled desks only):**

- Within each date's block, partition `sortedEntries` by `entry.shift?.templateName ?? null` (the
  `null` bucket is the "no shift assigned" group).
- Sort groups by shift start time ascending, tie-broken alphabetically by template name; the `null`
  ("No shift assigned") bucket always sorts **last**, regardless of any agent's actual times — an
  edge case is surfaced at the bottom, not hidden mid-list.
- Each group renders a **header bar** above its rows: background `#f3f4f6` (Secondary/table-header
  token, unchanged from existing usage elsewhere on this page), padding `12px` (house exception),
  text `"{templateName} · {startTime}–{endTime} · {N} agent(s)"` (Label role, 13px/600) — or,
  for the null bucket, `"No shift assigned"` (muted `#9ca3af`, **not** amber/warning-styled: per
  ENVL-01/02/06/07's guarantees this bucket should be structurally empty in a correct solve, so it is
  not treated as a validated warning state — any actually-wrong agent inside it still gets the
  existing red-name violation treatment on its own row, which already carries that signal).
- Beneath each group's header bar, the *same table structure* already in place (Agent name / Hours /
  per-timeslot cells) renders scoped to just that group's entries — the `slots` column set stays
  computed once per date (unchanged), so cells still line up across every group.
- The day-level `Total` row and `Unfilled` row (both pre-existing) render exactly once, after **all**
  groups, unchanged from today — the per-group header's headcount is a second, finer-grained view of
  the same fact the Total row already shows for the whole day, not a replacement for it.
- The specialty filter, date filter, and legend are computed and applied exactly as today, before and
  independent of this grouping — grouping only changes how already-filtered rows are partitioned for
  display.

**Slot-scheduled desks:** no header bars, no partitioning, no new field access — the exact same single
table this page renders today.
