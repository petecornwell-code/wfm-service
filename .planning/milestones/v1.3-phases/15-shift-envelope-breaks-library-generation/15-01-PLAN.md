<objective>
Promote a shift template's break from one fixed offset to N break bands, end to end: schema,
entity, service validation, DTO, and the coverage predicate. This is the data half of ENVL-08 and
the enabling change for SHLB-07 (per D-09, the band schema ships WITH generation, ahead of the
envelope work), plus two safety nets this project's own history demands.

Purpose: Phase 14 shipped `shift_template.break_offset_minutes` as a single offset, so every agent
on a shift breaks at the same minute — on the live StubHub (EN) library ~15 Early-shift agents all
break 12:00–13:00. Bands are the mechanism that gives the solver something to distribute; nothing
downstream in this phase can be built against the Phase 14 columns because D-01 drops them.

Output: `shift_template_break_band` exists and is populated, `shift_template` has lost two columns,
`covers()` is any-band, band capacity shortfall is surfaced as an advisory, and a dependency-free
guard reconciles the migration DDL against the entity mappings.
</objective>

<assumption_delta_decision>
The assumption-delta detector fired on this phase with `kind: pluralization`, correctly: Phase 14's
singular `shift_template.break_offset_minutes` loses its monopoly to N break bands. The decision is
already taken in `15-CONTEXT.md` D-01 and is recorded here, not re-derived.

- **Primary noun:** the break **band**. A break is now a band-valued concept; a template's break is
  the set of its bands.
- **Decision: `promote`.** Bands become primary and the singular columns are **dropped**, not kept
  alongside. Keeping both would be the audit NEW-1 shape — two fields that can disagree about one
  fact — which this project has already been burned by twice (NEW-1: the legacy
  `contractedHoursPerDay` scalar beside the per-day columns; I-1: model beside view). It is also the
  same trap Phase 14's D-10 refused when it rejected an `active` boolean beside the effective-date
  range. One mechanism, one predicate.
- **Consequence encoded as a test (Task 2):** exactly one band on a template must reproduce the old
  single-offset behaviour identically, so the promotion is behaviour-preserving at the boundary.
</assumption_delta_decision>

<planner_decisions>
- **P-01 — no `@OneToMany`.** `grep -rl "OneToMany" src/main/java/com/wfm/model/` returns zero files;
  every parent/child relationship in this codebase (`AgentDayHours`→`Agent`,
  `AgentAssignment`→`Timeslot`, `StaffingRequirement`→`Timeslot`) is child-owns-the-FK plus a
  repository query. Do not introduce this codebase's first parent-side collection mapping.
  `ShiftTemplateBreakBand` owns `shift_template_id`; callers load bands through
  `ShiftTemplateBreakBandRepository`.
- **P-02 — net hours becomes band-parameterised.** `ShiftTemplate.getNetHours()` takes the band's
  duration as a parameter; a template with zero bands has net hours equal to its full envelope.
  `getBreakStartTime()`/`getBreakEndTime()` move off `ShiftTemplate` onto `ShiftTemplateBreakBand`
  as `getBreakStartTime(ShiftTemplate)` / `getBreakEndTime(ShiftTemplate)`.
- **P-03 — one coverage implementation, reachable from generation.** `covers` stays a single static
  predicate on `ShiftLibraryValidationService`, generalised to take the template's band list, and is
  exposed through a public wrapper so `ShiftLibraryGenerationService` (plan 15-02) calls it rather
  than reimplementing it. D-08's one-implementation guarantee is unchanged.
- **P-04 — capacity semantics.** Blank/null capacity means unlimited (D-03). A capacity of `0` is
  rejected at save with a named message. A negative capacity is rejected by the same check.
- **P-05 — duplicate bands rejected at save.** Two bands on one template with the same `(offset,
  duration)` pair collide; bands whose break windows merely touch are distinct and legal.
- **P-06 — the capacity-shortfall risk gets one implementation and two callers**, exactly the shape
  D-08 (Phase 14) established for the coverage validator. This plan builds the predicate and wires
  the non-throwing advisory caller; plan 15-06 wires the pre-solve refusal caller. The advisory an
  operator reads and the refusal that stops their solve can never disagree.
- **P-07 — the migration blind spot is closed without a new dependency.** `application-test.yml`
  sets `flyway.enabled: false` with `ddl-auto: create-drop`, so migration SQL never executes in CI;
  V39 shipped a `CHAR(7)`-vs-`varchar(7)` mismatch that applied cleanly and then failed application
  boot, with a fully green 402-test suite (UAT gap G-14-1). Testcontainers would close it but
  violates this phase's no-new-dependency constraint. Instead, a plain JUnit test parses the
  migration SQL and reconciles declared column names and SQL types against the entities' `@Column`
  mappings. This catches the exact G-14-1 failure class at zero dependency cost.
</planner_decisions>

Generalise `covers` per D-02 to any-band coverage: a demand window is covered when the template's
weekday set contains the window's day, the window falls inside the template's effective range, the
window sits inside the envelope, and **at least one** of the template's bands leaves that window
worked — that is, at least one band whose break interval does not overlap the window. A template
with zero bands covers every window inside its envelope, which is exactly Phase 14's zero-duration
behaviour. A template with exactly one band evaluates to the identical verdict Phase 14's single
offset produced, because the any-band quantifier over a one-element set is the element itself. This
is what lets a single banded template self-cover its own break hour, and it is why SHLB-07 can emit
one banded template where the hand-built StubHub (EN) library needs an overlapping pair. Coverage
stays structural, not capacity-aware — D-04 (Phase 14) is untouched, and D-02 explicitly rejects
capacity-weighted coverage.

Change `covers`'s signature to take the template's band list alongside the template and window, and
add a public wrapper method that `ShiftLibraryGenerationService` (plan 15-02) will call, so
generation reuses this predicate rather than reimplementing it (P-03). Load bands once per
`validate(...)` call through the bulk repository method rather than per template inside the loop.

Generalise `isTemplateAligned` the same way: the template's own start and end must align, and every
band's computed break start and break end must align. Generalise `findHoursAdvisories` and
`findUnsatisfiableWeekdays` to compare each band's net hours (the band-parameterised
`getNetHours`) against agents' contracted hours through the existing
`BigDecimals.normalize(...).compareTo(...)` exact-equality helper — a template is hours-satisfiable
on a weekday when at least one of its bands yields a net duration some agent's contracted hours on
that weekday matches exactly. No tolerance band is introduced; Phase 14 D-07 settled exact equality
