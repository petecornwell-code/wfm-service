<objective>
Prove the guard can go red, and write down the rule that stops the next person repeating G-15-29.

Plan 15-14 builds the guard and it passes. A guard that has only ever passed is exactly as
trustworthy as the acceptor test suite that shipped a sevenfold regression green — which is to say,
not at all. `ShiftEnvelopeGroundTruthTest` already settled the discipline for this codebase: its
Task 2 exists because "a check that has never failed proves nothing about its ability to fail," and
it earns its keep by corrupting a clean solved schedule six different ways and asserting the walker
flags each one, exactly once.

This plan does the same for the three structural invariants, and adds one proof the phase has not
had before: a mechanical demonstration that the reported score can go blind to a defect the walker
still sees. Take a solved schedule, inject a hole, then set `shiftWorkContiguityWeight` to zero and
re-explain. The per-constraint violation-count table stops reporting the constraint entirely — that
is what a weight change does to score-shaped evidence — while `findSplitShifts` still returns the
hole. That is the whole argument of G-15-29 reduced to an assertion, and it is what makes "compare
violation counts, not raw hard scores" a demonstrated rule rather than a slogan.

Purpose: make the guard's ability to fail a tested property, and put the comparison rule somewhere
an engineer hits it before repeating the twelve-solve session.

Output: red-proofs in the guard, the comparison rule documented in `15-BENCHMARK.md`, and the two
gap entries closed with measured evidence.
</objective>

3. `redProof_INV1_aNullShiftPairIsFlagged()`. Set one `AgentShiftAssignment`'s `shiftBandPair` to

   dropping the shift assignment became the cheapest way to hide a split. The walker must not have
   the same blind spot.

4. `redProof_INV2_aBreakWithNoWorkOnOneSideIsFlagged()`. On a clean solve, pick an agent-day and
   `unseat` every held slot on ONE side of its break window. Assert `findEdgeBreaks` has size 1,
   names that agent-day, and its `reason` identifies the operational case. This is the Mariami
   Katcheishvili shape (a full worked run with the break bolted onto its boundary) made detectable.

5. `redProof_INV3_anUnstaffedEdgeHourIsFlaggedForThatDateAndHourOnly()`. On a clean solve, `unseat`
   every agent holding a seat at the 08:00 hour on one date — 08:00 is sole-routed to

configuration, so none of them carries search variance. Say so in the class javadoc: the red-proofs
are deterministic by construction, which is what makes them safe to run in the default suite
