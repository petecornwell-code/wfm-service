Give the operator the bulk path: seven `Usual Shift Monday` … `Usual Shift Sunday` columns in the
per-desk upload template, pre-filled with what is already stored, editable, and read back on
re-upload — with `clearDesk` wiping usual shifts the same way it already wipes day-hours.

the wipe. That order is not stylistic — reversing it opens a window in which an operator
downloading the template to fix one agent's hours wipes every stored usual shift on the desk.

Output: the template generator's pre-fill and sheet-scoped dropdown, the parser's seven-column read
loop with D-07/D-08/D-03 cell semantics, the `clearDesk` call site, and two new test classes.

<planner_decisions>
- **P-11 — The seven Usual Shift headers are REQUIRED headers on an enriched-shape sheet.**
  16-PATTERNS.md flagged this as needing a plan-time ruling: D-07 makes a blank *cell* valid, but it
  says nothing about a missing *column*. The three candidate rulings and why this one wins:
  *tolerate a missing column group* would let a pre-Phase-16 workbook clear every usual shift on the
  desk (D-11 fires) and re-supply none (no columns to read) — reintroducing, through a side door,
  precisely the wipe hazard D-09 exists to close. *Make the clearDesk wipe conditional on the sheet
  carrying the columns* keeps old workbooks working but contradicts D-11's literal wording and adds
  a second, subtler rule to a method whose whole value is being unconditional. *Require them* reuses
  the mechanism already in `DeskAssignmentUploadService`: a sheet missing a required header is
  skipped with a specific notice and the desk is **not** cleared — the CR-01 safety property, which
  is exactly the outcome an old workbook should get. The operator re-downloads the template once.
  D-06's own reversibility note already prices this in: *"the workbook shape is an operator-facing
  contract; ... every operator re-downloads the template again, the same disruption v1.2 spent a
  decision on when it retired the flat enriched shape."*

- **P-12 — The parser matches template names trim-and-case-insensitively; ambiguity is a skip.**
  `EnrichedColumnLayout.normalize` (trim + lowercase) is applied to both the cell value and each live
  template name. Rationale: D-10's dropdown can be bypassed by pasting, and an operator typing
  "early" for "Early" is exactly the typo D-08 was written for — resolving it is better service than
  warning about it. The cost is a collision case, handled explicitly: when two live templates
  normalize to the same key, the cell is skipped and the warning names the ambiguity rather than
  silently picking one. Note this is the OPPOSITE convention from era resolution
  (`UsualShiftResolutionService`, which matches exactly) — deliberately so: era resolution's key
  comes from a stored FK row and is byte-identical by construction, whereas a spreadsheet cell is
  human-typed. Both conventions must be stated in code comments so a later reader does not
  "unify" them.

- **P-13 — The upload parser writes `AgentUsualShift` rows directly through the repository, not
  through `UsualShiftService.setUsualShift`.** This mirrors Phase 10 exactly: the parser writes
  `AgentDayHours` rows directly in its row loop while `DeskAgentService.setDayHours` is the inline
  choke point. ROADMAP success criterion 3's choke-point requirement is scoped to USHF-03 (the
  inline roster edit); the bulk path is criterion 2's. Forcing the bulk path through `setUsualShift`
  would contradict D-08 (that method rejects with 400; D-08 requires skip-and-warn) and would turn a
  bulk import into an N-query path with a per-cell tenant/desk resolution and flush. The
  consequence — a second production writer of `AgentUsualShiftRepository` — is not hidden: it
  becomes an explicit row in plan 16-04's USHF-05 write-path table and an entry in the D-14
  structural guard's allowlist, which is what that table and guard exist for.

- **P-14 — The dropdown degrades gracefully in three named cases and is never partially applied.**
  Skip attaching data validation for a sheet when (a) the desk has zero live templates, (b) the
  comma-joined name list exceeds 255 characters, or (c) any live template name contains a comma or a
  double-quote (POI's `createExplicitListConstraint` joins the array into one comma-delimited
  formula string, so such a name would silently split into two bogus options). In all three the
  headers and pre-filled values are still written and the parser's own validation still applies —
  D-10 states the dropdown "does not replace parser validation", which is what makes degradation
  acceptable rather than a gap. The hidden-sheet / named-range formula-list fallback
  (16-RESEARCH.md Pattern 5) is deliberately NOT built: it is documented as an escape hatch for a
  library size no desk in this project has ever reached.

- **P-15 — Usual Shift columns occupy template indices 14–20; Specialty 1/2 move to 21/22.**
  Placed immediately after the day-hours group, matching D-18's export placement, so template and
  export are one shape and an exported sheet is directly re-uploadable. The row writer's existing
  comment about which columns are intentionally left blank must be updated to say 7–13 and 21–22 are
  blank and 14–20 are pre-filled.
</planner_decisions>
