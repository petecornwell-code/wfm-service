<objective>
Give the operator the one genuinely new action this phase introduces, on the page REST-06's wording
names.

A Rest Waivers section below the existing exceptions table on `AgentExceptions.tsx`: a heading, one
muted helper line explaining the waiver's direction in operator language, an immediate Add form, and a
Date / Reason / Actions table. Plus the TypeScript contract it consumes.

Purpose: REST-06 says "through the existing per-agent exception mechanism", and D-07 reads that as
this surface rather than the `agent_exception` row. The page is already scoped by desk and agent URL
parameters exactly as REST-06 needs, so a second route would duplicate that scoping for no benefit.

One design point must survive implementation unchanged. The exceptions table above is
local-optimistic-then-batch-`Save All`, because an operator typically edits several dates for one
agent at once. A rest waiver is the opposite shape — rare, single-row, mandatory-reason — so Add and
Delete each call the server immediately, with no batch step and no local-only pending state. That
difference is deliberate and must not be "corrected" into consistency with the table above it.

Output: the waiver and disclosure types plus the `restWaivers` API object in `client.ts`, and the new
section on `AgentExceptions.tsx`.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
