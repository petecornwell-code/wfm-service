<objective>
Land the two contracts the allocation grid needs, and the module that will make its seven defects
into compile errors.

Purpose: `ScheduleResults.tsx` carries seven confirmed sites that compare, sort or subtract HH:MM
strings without any notion of a day-start anchor. None of them can be fixed without the anchor
reaching the page, and none of them should be fixed with a bespoke local helper — the frontend has
no test runner, so a structural scan guard in the backend's mould has nowhere to live. A branded
numeric return type gets the same property from the compiler instead: once every anchored
accessor returns a branded offset rather than a string, a raw comparison stops compiling and all
seven sites become build errors until converted.

The anchor is part of a solved schedule's identity — it is what the score was computed against —
so it rides the schedule payload rather than being fetched from the desk, where a later re-anchor
could disagree with the schedule being displayed.

Output: the anchor on both payloads, the violation fields on the TypeScript side, and a new
`dayWindow.ts` with no consumers yet. 21-10 converts the page against it.
</objective>

Port the backend's anchored arithmetic, and make its return type unusable as a raw string.

1. Create `frontend/src/utils/dayWindow.ts`. Export a branded numeric type —
   `export type DayOffset = number & { readonly __brand: 'DayOffset' }` — so a value of this type
   cannot be produced by ordinary arithmetic on a plain number and a plain string cannot be
   compared with it. This is the whole mechanism: it is what turns a raw comparison into a build
   error on a surface with no test runner.
2. Export a factory mirroring the backend's binding call —
   `export function anchoredAt(dayStart: string): DayWindow` returning an object whose methods are
   bound to that anchor — and name every method after its backend counterpart so the two mental
   models stay aligned for a future maintainer: `anchoredStartMinute`, `anchoredEndMinute`,
   `anchoredDurationMinutes`, `anchoredContains`, `anchoredToHHMM` (the counterpart of the
   backend's to-local-time conversion), `anchoredPlusWithinDay`. Export `MINUTES_PER_DAY`.
3. Reproduce the backend's positional rule exactly, and state it in the module's own doc comment:
   a time equal to the anchor is minute zero in a START position and a full day in an END
   position. `anchoredStartMinute` and `anchoredEndMinute` must differ on exactly that case and
   nowhere else. `anchoredDurationMinutes` must wrap forward across the anchor rather than
   returning a negative value — the three-branch shape in the backend's implementation, quoted in
   this plan's interfaces block, is the specification.
4. Return `DayOffset` from every minute-producing function, and accept `DayOffset` wherever a
   caller would otherwise pass a raw number of minutes-from-anchor. Accept plain `string` for an
   HH:MM input and normalize seconds off it internally, so callers do not need a separate
   normalization step before every call. Do not export an unbranding helper, a cast helper, or a
   function returning a plain `number` for an offset — any of those reopens the hole the brand
   exists to close.
5. Also export the two date helpers the grid's business-day disclosure needs, ported from the
   backend statics: a business-date-from-calendar-date-and-time function and a
   calendar-date-from-business-date-and-offset function. Reproduce the backend's documented

6. Add no dependency. Add no test file and no test configuration: the compiler is the guard here
