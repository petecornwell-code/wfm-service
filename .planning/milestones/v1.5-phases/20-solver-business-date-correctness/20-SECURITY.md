## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| API/Backend -> solver (pre-solve refusal) | `requireShiftEnvelopeSeatSupply` runs in the request-handling thread before a solve starts, and its refusal is what an operator sees instead of an impossible schedule. It consumes already-validated internal state, not untrusted request input. | *(declared in 20-04)* |
| API/Backend -> operator (read path) | Both services produce what an operator reads: a coverage report and a generated shift library. No request field is parsed and no new endpoint is added; the change is which of two existing accessors a key position calls. | *(declared in 20-06)* |
| Operator -> API (demand upload) | A tenant-scoped request payload of timeslot and specialization ids with required FTE values. Already validated up-front by the service for payload uniqueness and for the existence and tenant/desk ownership of every referenced timeslot and specialization; this plan changes neither validation. | *(declared in 20-07)* |
| API/Backend -> Database (destructive delete) | A live-requirement delete scoped by tenant, desk, null schedule id and a date range. This plan changes which date system that range is expressed in, on one of its three callers. | *(declared in 20-07)* |
| Operator -> API (day-start save) | A tenant-scoped request carrying a single time value, through an endpoint that already exists. This plan widens which values are kept and adds no field and no endpoint. This is the phase's only input-validation change. | *(declared in 20-08)* |
| Operator -> API (spreadsheet upload, generation) | Where the per-call generation increment is inferred and the tiling refusal becomes reachable. This plan adds no code on that path; it makes an existing refusal reachable by widening the day-start range upstream of it. | *(declared in 20-08)* |
| client → `POST /api/v1/desks/{deskId}/timeslots/generate` | An untrusted path variable (`deskId`) and request body (period dates, window times, increment) cross here; the endpoint is live and already exposed by `frontend/src/api/client.ts` | *(declared in 20-09)* |
| caller tenant → desk row | `TenantContext` is the only thing scoping which desk a caller may read; this task adds a NEW desk read on that boundary | *(declared in 20-09)* |
| client → `PUT /api/v1/desks/{id}/day-start` | An untrusted time value crosses here and is persisted as desk state every later generation and solve reads | *(declared in 20-09)* |
| persisted desk anchor → solver seat expansion | A desk's stored day start determines each timeslot's business date; the seat expansion consumes that derived value and decides how many fillable seats exist. No untrusted input crosses here — the boundary is between stored state and a derived planning decision. | *(declared in 20-10)* |
| pre-solve seat supply → solver search | Under- or over-provisioned filler seats change what the solver is able to produce; the defect's blast radius is a wrong schedule, not a disclosure. | *(declared in 20-10)* |
| persisted desk anchor → pre-solve validation | A desk's stored day start determines each timeslot's business date; pre-solve validation decides whether a solve is allowed to start at all. No untrusted input crosses here — the boundary is between stored state and an availability decision. | *(declared in 20-11)* |
| pre-solve refusal → operator | A refusal is the only signal an operator receives; a spurious one makes a legal desk unsolvable with a message that names the wrong cause. | *(declared in 20-11)* |
| tenant → persistence | Every fetch in scope is tenant- and desk-scoped (`tenantId`, `deskId` parameters); the change edits only the DATE bounds and leaves both scoping parameters untouched | *(declared in 20-12)* |
| request → solve/accept | `periodStartDate`/`periodEndDate` originate in a `SolveRequest` payload and are the bounds this plan widens by one calendar day before narrowing in memory | *(declared in 20-12)* |

Eight of the twelve plans declare **no boundary crossed** — their tasks add test-scope code, in-process solver facts, or javadoc only, with no endpoint, no request parsing and no persisted write.
