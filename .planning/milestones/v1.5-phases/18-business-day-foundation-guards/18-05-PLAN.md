  keep the tree compiling. `PostgresBackedTest`'s own javadoc records that the container is a JVM-wide
  singleton and asks that the number of Postgres-backed classes stay small and related assertions be put
  together — so the round-trip assertions go into that class rather than a new one.

  incidental tidying.** The salvaged resource and guard carry, verbatim: "Phase 21 (SOLV-01)",
  "Phase 19 (`DayWindow` re-anchoring)", "Phase 20 (overnight shift templates)", "Phase 15", "Phase 17",
  "Plan 18-01", a task identifier of the form T-18-nn, and several decision-document identifiers. Under
  v1.5's numbering the first three are wrong by one or two phases each — these exact lines are the
  evidence D-24 was written from, and this is the second renumbering they would have survived. Every one
  is rewritten to state its reason inline and to cite the requirement ID (`SOLV-01`, `BDAY-04`, `OVNT-01`)
  rather than a phase number, a plan number or a decision identifier.

- **P-25 — A skipped Postgres run is treated as a failure, checked against the JUnit XML report.**
  `PostgresBackedTest` sets `disabledWithoutDocker = true`, so an absent or unreachable Docker daemon makes
  the whole class skip and the Gradle invocation exit 0. Its own javadoc names the sharp edge: a skip is
  not a pass. The blocking task therefore asserts against
  `build/test-results/test/TEST-com.wfm.repository.MidnightTimeslotPostgresTest.xml` that the class ran with
  zero skipped tests, and carries a `<precondition>` so an executor halts on an unreachable daemon instead
  of recording a vacuous green. `build.gradle` pins Testcontainers at 1.21.4 specifically because older
  versions fail Docker 29's API negotiation and surface it as exactly this silent skip.
