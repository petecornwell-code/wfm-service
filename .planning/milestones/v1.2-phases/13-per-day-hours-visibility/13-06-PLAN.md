<planner_decisions>
- **P-16 — the rollback proof is feasible against the existing harness, and is planned rather than
  deferred.** The orchestrator asked for an explicit feasibility judgement. Verdict: **feasible**,
  with three specific harness facts making it so. (a) `spring-boot-starter-test` on Spring Boot 3.4.2
  ships Spring Framework 6.2, which provides
  `org.springframework.test.context.bean.override.mockito.MockitoSpyBean` — no new dependency.
  (b) `@DataJpaTest` wraps each test in a rollback-only transaction, which would make a service-level
  rollback unobservable; `@Transactional(propagation = Propagation.NOT_SUPPORTED)` on the single test
  method suppresses that wrapper so `setContractedHours` opens and commits its own real transaction
  and the post-failure state is genuinely readable. (c) The failure can be injected without
  `callRealMethod()` — which a `delegatesTo`-backed spy over a Spring Data JDK proxy cannot support —
  by stubbing only the argument-matched `THURSDAY` row write, so the other six calls fall through to
  the spy's delegation untouched. `DayOfWeek.values()` runs MONDAY-first, so THURSDAY is literally
  row 4 of 7, exactly the failure point `13-VERIFICATION.md`'s `behavior_unverified_items` prescribes.
  Reversibility: reversible.

- **P-17 — the WR-02 proof is a direct handler unit test, not a new `@WebMvcTest` harness, and the
  residual HTTP-level gap is declared rather than papered over.** This codebase has zero
  `@WebMvcTest`/`MockMvc` tests, and its web layer includes a `TenantFilter`, so introducing that
  harness is a new-pattern decision with unknown friction and a blast radius beyond this gap-closure
  run. A direct unit test on `GlobalExceptionHandler` proves the response the handler produces (400,
  code, non-leaking body) deterministically; Spring's most-specific-handler dispatch is framework
  behaviour. What it does not prove is the end-to-end route from a malformed URL to that handler —
  that stays an explicit human-check, already tracked as WINDOWS.md item 4 and item 3 of
  `13-VERIFICATION.md`'s Human Verification Required list. Reversibility: reversible.

- **P-18 — the range rejection message names the field, not just the range.** `setDayHours` throws
  "Hours must be between 0 and 24"; the bulk endpoint throws
  "Contracted hours per day must be between 0 and 24". The bulk failure surfaces through
  `showToast('error', getErrorMessage(err))` with no weekday prefix, so the message is the entire
  sentence the operator reads and needs to name what it is about. The pre-existing
  `setContractedHours_negative_isRejected` asserts only the exception type, so the message change
  breaks no test. Reversibility: reversible.

- **P-19 — the new handler narrows one exception type; the catch-all is untouched.** Replacing or
  broadening `handleUncaught` would silently reclassify unrelated failures across every controller in
  the application. Only `MethodArgumentTypeMismatchException` is intercepted, and it is placed beside
  the other binding-failure 400 so the file's grouping stays readable. Reversibility: reversible.
</planner_decisions>
