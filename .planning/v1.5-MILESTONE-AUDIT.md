## Verdict

The milestone's five phases each verified `passed` on their own terms, and all 29 requirements
trace cleanly through three independent sources. The gap is at a seam no single phase owned:
**Phase 21 made shifts able to span midnight, and Phase 22's rest arithmetic cannot measure a gap
that starts from one.**

That is precisely the risk the milestone's own requirements text identified when it made minimum
rest a hard constraint — "enabling overnight shifts without it would *create* a way to produce
illegal back-to-back rosters that score `0hard`." The constraint was built, and it is correct for
same-day predecessors. For an overnight predecessor it overstates the gap and stays silent.

### G-1 — the critical gap

`RestSpan.gapMinutes` (`RestSpan.java:120-130`):

```java
DayWindow window = DayWindow.anchoredAt(prev.dayStart());
int remainingInPrevDay = DayWindow.MINUTES_PER_DAY - window.anchoredEndMinute(prev.endTime());
int elapsedIntoNextDay = window.anchoredStartMinute(next.startTime());
return remainingInPrevDay + elapsedIntoNextDay;
```

`anchoredEndMinute` receives `prev.endTime()` and nothing else. It cannot know whether that end
time wrapped past the anchor. `anchoredDurationMinutes` gets this right elsewhere precisely
because it is handed both start and end together.

Measured against the compiled production class at a `00:00` anchor — every live desk's current
real value:

| Case | Computed | True | Verdict |
|---|---|---|---|
| prev 14:00–22:00 → next 06:00 (control) | 480 | 480 | ✅ correct |
| prev 22:00–06:00 → next 14:00 | 1920 | 480 | 🔴 4× over |
| prev 22:00–06:00 → next 07:00 | 1500 | 60 | 🔴 25h reported for 1h rest |

The third case is the operational one: against an 11-hour minimum, a one-hour real rest is reported
as compliant. The error direction is unsafe — it overstates rest, so the hard constraint
under-fires and the illegal roster scores `0hard`.

It is reachable in live solving, not only on the historical-lookback path: the in-horizon
predecessor stream is built at `ScheduleConstraintProvider.java:1052` from assigned
`shiftBandPair` templates, which OVNT-01 explicitly permits to span midnight.

**Real defect, and separately a coverage gap.** These are distinguished deliberately — this project
has a documented history of a review conflating the two. The defect is in production arithmetic.
The reason it shipped is that no test builds an overnight predecessor: the only overnight template
in the rest suites sits in the *successor* position, where the formula is accidentally correct.
