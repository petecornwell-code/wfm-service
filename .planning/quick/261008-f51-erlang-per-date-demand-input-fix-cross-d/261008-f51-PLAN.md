<objective>
Make Erlang C and Erlang X demand input on Staffing Requirements work per business date. Fix the cross-day wipe, add server-side copy-to-dates, and save the inputs so reopening a date reloads them.

Purpose: today the Erlang grid shows only the first date, but Calculate deletes live demand for the whole period. It then re-inserts rows for the first day only, so days 2..N end with zero demand while the page says every day received the same parameters. Locked operator decisions OD-1..OD-4 (from the task description) define the replacement behaviour:
- OD-1: the operator picks one business date, and Calculate replaces that date only.
- OD-2: an optional copy of the result to selected dates or weekdays, done server-side in one transaction.
- OD-3: inputs are persisted per desk, timeslot and specialization, with a GET to reload them.
- OD-4: the misleading copy is fixed.

Output:
- Backend: a RED-first reproducer test, a reshaped request DTO (businessDate + copyTo), and one shared helper for both calculators.
- Persistence: a V56 erlang_demand_input migration with its entity, repository and GET endpoint, plus a real-Postgres test.
- Frontend: a business-date picker, a copy panel and input reload.
- Docs: spec.md updated.

The scratchpad Erlang Calculator page (ErlangCalculator.tsx, /calc endpoints) is OUT OF SCOPE and must not change.
</objective>
